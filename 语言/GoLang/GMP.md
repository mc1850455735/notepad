# 核心概念

GMP 模型是 Go Runtime 实现 Goroutine 调度的核心机制，通过将大量的 Goroutine 高效的调度到少量的操作系统线程上运行，实现了高并发，同时降低线程切换和关键的开销。

GMP 含义如下：
- G：Goroutine，Go 中的轻量级协程，表示一个待执行的任务；
- M：Machine，操作系统的线程，真正负责执行代码；
- P：Processor，**逻辑处理器**，负责提供运行 Go 代码所需的**调度资源**；

一个 M (系统级线程) 必须拥有一个 P (协程调度器)，才能执行 Goroutine 中的代码，

创建 Goroutine 的过程并不是创建线程并执行的过程，只是创建对应的 G 并将这些 G 加入到**运行队列**当中，随后，P 关联的 M 会不断从队列中取出任务并执行。

# 本地队列和全局队列

每一个 P 都有一个自己的**本地队列**，调度时，优先从自己的本地队列中获取 G。

除此之外，还存在一个**全局队列**，本地队列中至多存在 256 个待运行的 G，当队列满时，调度器会将部分任务转移到全局队列。通过本地队列和全局队列分离，可以降低多个线程争抢全局队列锁的开销。

# 工作窃取

假如现在存在两个逻辑处理器 P1、P2，如果 P1 存在很多任务而 P2 的执行队列中没有任务时，就可以执行工作窃取，从 P1 的本地队列中窃取一部分到自己的本地队列中，通过这种方式提高 CPU 运行效率，避免一个 P 很繁忙但是另一个 P 空闲的情况发生。

# 线程移交

假设 M1 在执行一个 G 时，发生了如写操作等阻塞的系统调用，此时为了避免 M1 相关联的 P1 也被长期占用，通过线程移交，将 P1 交给另一个 M2。

值得注意的是，实际情况下，Goroutine 并不会因为读写操作就阻塞掉一整个系统线程，而是会使用。。。

# 抢占式调度

如果某一个 goroutine 长期执行，则 go runtime 可以在适当的时机抢占他，保证其他的 go routine 可以被执行。
