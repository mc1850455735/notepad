
# 概述

- 类的生命周期描述了一个类加载, 使用, 卸载的整个过程
- 生命周期分为5个阶段: 加载->连接->初始化->使用->卸载
- 其中, 连接又可以分为3个阶段: 验证->准备->解析
- 初始化阶段中, 程序员可以进行干涉, 所以相对更重要

# 加载阶段

### 概述
1. 加载阶段的第一步是**类加载器**根据类的全限定名通过**不同渠道**以二进制流的方式获取字节码信息
2. 类加载器在加载完类之后, Java虚拟机会将字节码中的信息保存到**方法区**中
- 方法区只是一个虚拟的概念, 旧版本存放在**永久代**区域, 新版本存放在**元空间**
3. 收集完字节码信息后, 会生成一个**InstanceKlass**对象, 保存类的所有信息, 里面还包含实现**特定功能**, 比如多态的信息(使用虚方法表实现)
4. JVM还会在**堆**中生成一份与方法区中数据类似的 `java.lang.Class` 对象, 在**JDK8**以及之后, 可以在Java代码中获取类的信息以及其存储的**静态字段**的数据 (反射的实现方式), 与InstanceKlass通过引用进行关联
- JDK8之前, 静态字段存放在方法区, 之后改为存放在堆区

**注意**
- 虽然在方法区和堆区中都存在着字节码对象, 但是方法区中的InstanceKlass对象是使用 C++语言编写的
- 对于开发者, 只需要访问堆中的Class对象, 而不需要访问方法区中的所有信息, 由此, JVM可以控制开发者可以访问数据的范围
- 方法区中类对象内容多于堆区中类对象内容, 堆中只暴露对象里必要的内容

**查看**
- 使用hsdb可以查看Java虚拟机内存信息, 位于JDK内lib文件夹的 `sa-jdi.jar`
- 注意版本要与欲检查的JVM版本一致
- 启动命令: `java -cp sa-jdi.jar sun.jvm.hotspot.HSDB`
- 使用 `jps` , 可以查看本机所有已启动的Java虚拟机进程及其进程号
- 在 Object Histogram 中, 可以看到虚拟机中不同类型对象的大小及其数量

# 连接阶段
- 连接分为三部分, 分别是验证, 准备, 解析

##### 验证
- 验证: 验证内容是否满足 `Java虚拟机规范`
- 主要目的是为了检测Java字节码文件是否遵守了 `Java虚拟机规范` 中的约束
- 这个阶段一般不需要程序员进行参与
- 主要包含如下4部分
	- 文件格式校验, 如魔数是否符合 `0xCAFEBABE`, 主次版本号是否满足Java虚拟机版本要求等
	- 元信息验证, 如一个类必须有父类, 即super不能为空
	- 验证程序执行指令的语义, 如方法内指令执行中跳转到不正确的位置
	- 符号引用验证. 如是否访问了其他类中的private方法等

##### 准备
- 准备: 为静态变量分配内存并设置**初始值**
- 该内存结构只适用于**JDK8**以及之后的版本, 8之前的版本后续章节详述
- 该处置初值并不由用户决定, 而是赋给一个默认的值, 通常为 0
- **final修饰**的基本数据类型静态变量会直接在准备阶段将代码中的值进行赋值 
- 这是由于final修饰的变量未来不会发生变化, 可以直接在编译阶段初始化值

##### 解析
- 解析: 将常量池中的**符号引用**替换成指向内存的**直接引用**
- 符号引用就是在字节码文件中**使用编号**来访问常量池中的内容

# 初始化阶段

### 概述
- 初始化阶段会执行**静态代码块**中的代码, 并为**静态变量**赋值
- 初始化阶段会执行字节码文件中 **clinit** 部分的字节码指令
- `putstatic <id>` : 从操作数栈中获取值, 设置到对应id的静态变量中
- 静态变量初始化和静态代码块初始化的顺序, 取决于**Java代码**中的先后顺序
- 非静态代码块在类对象创建时执行, 最终被编译进入类的构造函数中去, 非静态代码块的执行顺序在构造方法之前

### 类的初始化
- 添加 `-XX:+TraceClassLoading` 参数可以打印出加载并初始化的类
- 以下几种方法会导致类的初始化
1. 访问一个类的静态变量或者静态方法
2. 调用 `Class.forName(String className)` 
	- 对于 `forName`, 并不是传递后一定会被初始化, 只有设置了 `initialize` 参数为true(默认)后, 才会进行初始化
3. new一个该类的对象时
4. 执行一个当前类的main方法时

### 带继承的初始化
- 直接访问父类的静态变量, 只初始化父类, 不会触发子类的初始化
- 子类的初始化clinit调用前, 会先调用父类的clinit初始化方法

### clinit不执行情况
1. 无静态代码块且无静态变量赋值语句
2. 有静态变量的声明, 但是没有赋值语句
3. 使用以**常量赋值**的**final修饰**的静态变量, 对该变量的初始化在准备阶段完成
	- 如果用final修饰的静态变量**不以常量**赋值, 也会导致类初始化
4. 类的数组的创建不会导致数组中元素的类进行初始化
