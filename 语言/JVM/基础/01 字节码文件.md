# 概述

##### 什么是JVM
- `JVM` 全称 `Java Virtual Machine`, 中文译名为 `Java虚拟机`
- `JVM` 本质上是一个计算机上的程序, 职责是运行 `Java` 字节码文件

##### 功能
1. 解释和运行
	- 字节码经由虚拟机转换为机器码的过程即为 **解释**
	- `java` 文件通过 `javac` 编译成为 `class` 字节码文件, 字节码通过 `java` 运行
2. 内存管理
	- 自动为对象和方法等分配内存
	- 自动垃圾回收机制, 回收不再需要使用的对象
3. 即时编译 (JIT, Just-In-Time)
	- 对热点代码进行优化, 提升执行效率
	- 由于 `JVM` 需要进行实时解释, 默认情况性能不如 `C/C++`
	- 通过识别热点代码 (同一段事件内被多次调用), 对热点代码进行解释并优化, 将机器码保存至内存, 避免了多次调用时的反复解释

##### 常见JVM
- Java虚拟机规范: 由 `Oracle` 指定, 包含了虚拟机在设计和实现时需要遵守的规范, 主要包括 `Class` 字节码定义, 类和接口的加载和初始化, 指令集等内容
- Java虚拟机规范是对虚拟机设计要求, 不是对 Java 设计的要求, 虚拟机可以运行在其他语言 (如 `Groovy`, `Scala`) 生成的字节码文件之上
- 官网地址: https://docs.oracle.com/javase/specs/index.html

# 字节码文件详解

### JVM组成

**概述**
- 首先, `JVM` 使用 `ClassLoader` 将字节码文件加载到内存中
- 存放类对象的内存区域叫做 **运行时数据区域**, 这是 `JVM` 操作的数据区域
- 类被加载到内存中后, 虚拟机使用执行引擎执行代码 (即时编译器, 解释器, 垃圾回收器等)
- 本地接口可以调用本地中已经编译的方法, 如虚拟机提供的 `C/C++` 方法

### 字节码文件组成

**阅读字节码文件**
- 字节码文件中保存了源代码编译后的内容, 以二进制方式进行存储, 无法直接使用记事本打开并阅读
- 通过 `jclasslib` 进行字节码查看和阅读

**组成**
- 基础信息: 包含魔数, Java版本号, 访问标示, 父类和接口等
- 常量池: 保存了字符串常量, 类或接口名, 字段名, 主要在字节码指令中使用
- 字段: 当前类或接口声明的字段信息
- 方法: 当前类或接口声明的方法信息, 转为字节码指令保存
- 属性: 类的属性, 如源码文件名, 内部类的列表等

### 基础信息

##### 概述
- 基础信息中包含一般信息和它实现的一些接口
- 在 jclasslib 中, 分别在一般信息和接口项中进行显示

##### 魔数
- 四字节数据, 16进制为 `ca fe ba be`
- 由于文件实际上是不存在扩展名的区别的
- 软件通过文件的头几个字节 (文件头) 去校验文件的类型, 如果软件不支持该类型就会出错
- Java字节码文件中, 将文件头称为 magic魔数

##### 主副版本号
- 指的是编译字节码文件的 `JDK` 版本号
- 主版本号用来标示大版本号
	- JDK1.0-1.1使用了 45.0-45.3
	- JDK1.2 使用了 46
	- 此后每升级一个大版本版本号+1
- 副版本号是主版本号相同时的区分标识, 一般只需要关心主版本号
- 版本号的主要作用是用来判断当前字节码的版本和运行时的 `JDK` 是否兼容
- 主版本不兼容时, 可以通过 jclasslib 检查, 选择升级 JDK 或者更换依赖版本

### 常量池
- 作用: 避免相同内容**重复定义**, 节省内存空间
- 常量池中的数据都有一个编号, 从1开始, 在字段或者字节码指令中通过编号可以快速找到对应的常量池中数据, 这个过程叫做**符号引用**
- 常量字段中会存储常量池索引, 通过常量池索引找到对应常量的信息, 如果是字符串, 还需要通过引用信息找到字符串常量池中的值
- 为什么字符串值需要单独存放而不放在常量池中引用常量处, 因为可能存在其他位置使用字符串值, 如记录变量名等, 所以必须经过一层转包, 保证字符串值的独立性

### 方法
- 字节码中的方法区域是存放字节码指令的核心位置
- 方法中的Code属性存储的就是指令的字节码
- **操作数栈**是临时存放数据的地方, **局部变量表**是存放方法中局部变量的位置
- 局部变量表底层是一个数组, 不同的变量存放在数组的不同下标

**指令**
- `iconst_<x>` : 将值 x 加入操作数栈
- `istore_<i>` : 弹出操作数栈顶层的数, 将其存入数组中下标为 `i` 变量中
- `iload_<i>` : 复制一份数组中下标为 i 元素的值, 加入操作数栈中
- `iadd` : 将操作数栈中顶部两个值弹出并相加, 将计算结果存入栈中
- `iinc <i> by <x>` : 将下标 `i` 的变量值增加 `n` (直接加局部变量表, 不需要栈)
	- `++` 操作 和 `+=` 操作都使用 `iinc` 直接操作局部变量表实现
- `return` : 方法结束, 返回

**注意**
- `++i` 和 `i++` 在字节码中的区别即为 `iload` 和 `iinc` 的顺序, 也决定了先使用后执行还是先执行后使用

### 常用工具

- `javap -v` 命令, 直接输入 `javap` 查看可用参数
	- `javap` 是 `JDK` 自带的反编译工具, 可以通过控制台查看字节码文件的内容, 适合在服务器上查看字节码文件内容
	- 使用 `javap -v 字节码文件名称` 查看具体字节码信息, 如果是 jar 包, 需要现使用 `jar -xvf` 命令进行解压
	- `SpringBoot` 编写的 jar包字节码文件存放在解压后的 `BOOT-INF` 文件夹
 - jclasslib 有idea插件版本, 使用时可以看到编译后的字节码文件
	 - 每次查看不同的源码, 都需要重新点开 view 页面
	 - 要查看的源码必须编译后才可以看到最新的字节码
- Arthas
	- Arthas是一款线上监控诊断产品, 通过全局视角实时查看应用 load, 内存, gc, 线程的状态信息, 能在不修改代码情况下对业务问题进行诊断
	- `dashboard` : 控制台, 展示 jar 包的各类执行信息
	- `dump 类名` : 将已加载类的字节码文件复制到特定目录
	- `jad 类名` : 反编译已加载类的源码
