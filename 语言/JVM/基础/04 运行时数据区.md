
# 概述

### 简述
- Java虚拟机在运行Java程序过程中管理的内存区域, 称为运行时数据区
- *Java虚拟机规范* 中规定了每一部分的作用
- 可以按照是否线程之间共享, 将其分为两类

### 分类
**线程不共享**
- 程序计数器
- Java虚拟机栈
- 本地方法栈
**线程共享**
- 方法区
- 堆
- 直接内存

### 静态变量存储位置
- 在JDK6及之前的版本中, 静态变量存放在**方法区**中, 也就是**永久代**
- 在JDK7及之后的版本中, 静态变量存放在**堆**中的**Class对象**内, 脱离了永久代

# 程序计数器

### 概述
- 程序计数器 (Program Counter Register), 也叫 PC寄存器, 每个线程会通过自己的 PC 记录当前要执行的**字节码指令地址**
- 在**加载阶段**, 虚拟机将字节码文件中的指令读取到内存之后, 会将原文件中的偏移量转换成内存地址, 每一条字节码指令都会有一个内存地址
- 在代码**执行过程**中, 程序计数器会记录下一行字节码指令的地址. 当执行完当前指令之后, 虚拟机的执行引擎根据程序计数器执行下一行指令
- 程序计数器只会用来存储固定长度的地址, 不会出现内存溢出现象
	- **内存溢出**: 指的是程序在使用某一块内存区域时, 存放的数据需要占用的内存大小超过了虚拟机可以提供的内存上限
- 程序员无需对PC进行任何处理

### 作用
- 程序计数器可以控制程序指令的进行, 实现分支, 跳转, 异常等逻辑
- 在多线程执行情况下, Java虚拟机需要通过程序计数器记录CPU切换前解释执行到哪一句指令并继续进行解释

##### 跳转指令
- `ifne <n>`: 将操作数栈中的数与0进行比较, 如果相同则跳转到第n行

# 栈

### 概述
- Java中的栈分为两类
	1. **Java虚拟机栈**: 用来保存在Java中实现的方法 
	2. **本地方法栈**: 保存方法中用native标记的, 通过C++实现的方法
- Hotspot 中, 这两种类型的栈使用**同一个栈区域**进行保存

**虚拟机栈**
- **Java虚拟机栈** (Java Virtual Machine Stack) 采用**栈**的数据结构来管理和调用其中的基本数据, FIFO, 每个方法的调用使用一个**栈帧** (Stack Frame) 来保存
- 通过Idea中的debug工具, 可以查看栈帧的内容
- Java虚拟机栈随着线程的创建而创建, 而回收会在线程销毁时进行, 由于方法可能在不同的线程中执行, 每个线程都会包含一个自己的虚拟机栈

**栈帧的组成**
- 局部变量表: 存放运行过程中所有的局部变量
- 操作数栈: 虚拟机在执行指令的过程中用来存放临时数据的一块区域
- 帧数据: 主要包含动态链接, 方法出口, 异常表的引用

### 局部变量表
- 局部变量表的作用是在方法执行过程中存放所有的局部变量
- 编译成字节码文件时就可以确定局部变量表的内容
- 栈帧中的局部变量表是一个**数组**, 数组中的每一个位置称为**槽 (slot)**, long和double类型占用两个槽, 其余类型占用一个槽
- 为了节约空间, 局部变量表中的槽是可以**复用**的, 一旦某个局部变量不再生效, 当前槽就可以被再次利用

**局部变量表结构**
- 实例方法中, 局部变量表序号为 0 的位置存放的是this, 表示调用当前方法的对象, 运行时会在内存中存放实例对象的地址
- 方法参数也会保存在局部变量表中, 其顺序与方法中参数定义的顺序一致. 当三者同时存在时, 存储顺序为: `this对象->方法参数->方法体内局部变量`
- `Nr.` : 表示局部变量表中变量的编号
- `起始PC, 长度`: 限制局部变量的生效范围
- 序号: 变量在栈帧中的**起始位置**

### 操作数栈

- **操作数栈**是栈帧中虚拟机在执行指令过程中用来存放中间数据的一块区域, 是一种栈式的数据结构, 如果一条指令将一个值压入操作数栈, 则后续指令可以弹出并使用该值
- 编译器在**编译期**, 通过**模拟运行**的方式, 就可以确定操作数栈的**最大深度**, 从而在执行时正确分配内存大小

### 帧数据

- 帧数据主要包含动态链接, 方法出口, 异常表的引用
- 在这一部分, 不同的虚拟机可以根据自己的需要, 在实现最基本功能的基础上, 向其中添加自己需要的额外功能
- **动态链接**
	- 当前类的字节码引用了**其他类**的属性或方法时, 需要将符号引用转换成对应的运行时常量池中的内存地址. 动态链接就保存了编号到运行时常量池的内存地址的**映射关系**
- **方法出口**
	- 方法出口指的是方法在正常或者异常结束时, 当前栈帧会被弹出, 同时程序计数器应该指向**上一个栈帧**中的**下一条指令**的地址. 所以在当前栈帧中需要存储此方法出口的地址
- **异常表**
	- 异常表存放的是代码中的异常处理信息, 包含了异常捕获的**生效范围**以及异常发生之后跳转到的字节码指令位置

### 内存溢出
- Java虚拟机栈如果栈帧过多, 占用内存超过栈内存可以分配的最大大小就会出现**内存溢出**, 在栈内存溢出时, 会抛出 `StackOverflowError` 异常
- 通过虚拟机参数 `-Xss栈大小`, 可以指定虚拟机栈的大小, 栈大小可以指定单位为 字节 (默认, 必须为1024的倍数), `k或K`, `m或M`, `g或G`
	- 也可以用 `-XX:ThreadStackSize=栈大小` 调整标志配置堆栈大小
	- 如果不指定栈的大小, JVM将创建一个具有默认大小的栈, 具体大小取决于操作系统和计算机体系结构
- Hotspot JVM 对栈大小有最大值和最小值要求
	- 对 Windows(64位) 下的JDK8测试最小值为180k, 最大值为1024m
	- 超过该范围, 则配置不生效, 栈大小走默认值
- 局部变量过多, 操作数栈深度过大, 也会影响相同栈内存大小下栈帧的个数
- 一般情况下, 即使使用了递归, 栈深度也只会到几百, 不会出现栈的溢出, 所以可以手动调节此参数为 `-Xss256K` 以节省内存

### 本地方法栈
- Java虚拟机栈存储了Java方法调用时的栈帧, 而**本地方法栈**存储的是native本地方法的栈帧
- 在Hotspot虚拟机中, Java虚拟机栈和本地方法栈在实现上使用了**同一个**栈空间. 本地方法栈会在栈内存上生成一个栈帧用于临时保存方法参数, 同时便于出现异常时打印出本地方法栈信息

# 堆

**概述**
- 一般Java程序中堆内存是空间最大的一块内存区域, 创建出来的对象都存在于堆上, 该区域是最容易出现内存溢出的区域
- 栈上的局部变量表中可以存放堆上对象的引用. 静态变量也可以存放堆对象的引用, 通过静态变量可以实现对象在**线程之间共享**.
- 堆内存中有三个需要关注的值: used, total, max
	- used: 指当前已经使用的堆内存
	- total: java虚拟机已经分配的可用堆内存
	- max: java虚拟机可以分配的最大堆内存
- 如果不设置任何参数, max默认是系统内存的 `1/4`, total默认是系统内存的 `1/64`, 实际应用时一般都需要通过虚拟机参数手动设置 total 与 max
	- 设置total: `-Xms内存大小` , 要求必须大于 1MB
	- 设置max : `-Xmx内存大小` , 要求必须大于 2MB
- Java服务端程序开发时, 建议将 `-Xmx` 和 `-Xms` 设置为**相同的值**, 这样在程序启动之后可用总内存就是最大内存, 减少了向Java虚拟机申请堆内存以及分配堆内存的时间, 也避免了堆内存过剩时的堆收缩情况

**Arthas查看**
- 在arthas中, 可以通过 `dashboard` 调出控制台查看该信息, 同时可以通过 `-i 毫秒` 指定刷新频率, 默认5秒刷新一次
- 也可以使用 `memory` 指令, 只查看当前内存使用情况
- arthas中显示的heap大小与实际设置大小**不一致**, 这是因为arthas中的heap内存使用了 **JMX** 技术中的内存获取方式, 这种方式与**垃圾回收器**有关, 计算的是**可以分配对象的内存**, 而不是整个内存

**溢出**
- 堆内存大小是有上限的, 当对象一直向堆中放入对象达到上限之后, 就会抛出 `OutOfMemoryError` 错误
- 随着堆中对象增多, 当total可使用的内存即将不足时, java虚拟机会继续分配内存给堆, 当可分配空间不足时, 判定为**堆内存溢出**
- 并非只有当 `used=max=total` 时才能判断为堆内存溢出, 其判定条件比较复杂, 详见**垃圾处理器**部分

# 方法区

### 概述
- 方法区是存放基础信息的区域, 是线程共享的区域, 主要包含三部分内容
- 类的元信息: 保存了所有类的基本信息
- 运行时常量池: 保存了字节码文件中的常量池内容
- 字符串常量池: 保存了字符串常量

**设计**
- 方法区是 *Java虚拟机规范* 中设计的**虚拟概念**, 每块Java虚拟机对其实现都各有不同, Hotspot 设计如下
- JDK7及其之前的版本, 将方法区存放在**堆区域**的**永久代空间**, 堆的大小由虚拟机参数控制
	- 堆区域中**永久代大小**由虚拟机参数 `-XX:MaxPermSize=值` 控制
- JDK8及其之后的版本, 将方法区存放在**元空间**中, 元空间位于操作系统维护的**直接内存**中, 默认情况下只要不超过操作系统承受的上限, 就可以一直为其分配内存
	- 可以使用虚拟机参数 `-XX:MaxMetaspaceSize=值` 限制元空间最大大小
	- 一般设置为 256M

### 类的元信息

- 方法区是用来存储每个类的**基本信息 (元信息)** , 一般称为 **InstanceKlass** 对象. 在类的加载阶段完成

### 运行时常量池

- 方法区除了存储类的元信息之外, 还存放了**运行时常量池**. 常量池中存放的是字节码中的常量池内容
- 字节码文件中通过**编号查表**的方式找到常量, 这种常量池称为**静态常量池**. 
- 当常量池加载到内存中之后, 可以通过**内存地址**快速定位到常量池中的内容, 此时的常量池称为**运行时常量池**. 

### 字符串常量池
- 方法区中除了类的元信息, 运行时常量池之外, 还有一块区域, 被称为 运行时常量池 (StringTable)
- 字符串常量池存储在代码中定义的常量字符串内容
	- 对于两个字符串变量 a 和 b , 使用 `+` 进行字符串拼接时, 实际上在底层调用了一个 `StringBuilder` 对象
	- 对于两个字符串常量`"a"`和`"b",` 使用 `+` 进行字符串拼接时, 会在编译阶段直接指向字符串常量池中已经存在的字符串常量对象
- 早期设计时, 字符串常量池属于运行时常量池的一部分, 其存储位置也是一致的, 后续做出了调整, 将二者进行了拆分
	- JDK7之前: 运行时常量池**包含**字符串常量池, 方法区的实现为**永久代**
	- JDK7: 字符串常量池从方法区**拿到了堆中**, 运行时常量池还留在永久代
	- JDK8及之后: hotspot 使用元空间**替代**了永久代, 字符串常量池**留在堆中**
- `String.intern()` 方法可以手动将字符串放入字符串常量池中, 适合将重复使用字符串加入常量池, 使其多次被复用
	- JDK6中, intern() 方法会将第一次遇到的**字符串实例**复制到**永久代**的字符串常量池中, 返回永久代中对字符串实例的引用, 在 JVM 启动时, 就会将一些常用的字符串 (如java) 加入字符串常量池中
	- JDK7及之后版本, 字符串常量池在堆中, intern() 方法会把第一次遇到字符串的**引用**放入字符串常量池中; 对于常用的字符串 (如java), 会在JVM启动时直接将其实例放入字符串常量池而不是存放引用

### ByteBuddy
- 通过ByteBuddy框架, 可以动态生成字节码数据并加载到内存中
1. 引入依赖
```xml
<dependency>
    <groupId>net.bytebuddy</groupId>
    <artifactId>byte-buddy</artifactId>
    <version>1.12.23</version>
</dependency>
```
2. 创建ClassWriter对象
```java
ClassWriter classWriter = new ClassWriter(0);
```
3. 调用visit方法, 创建字节码数据
```java
classWriter.visit(Opcodes.V1_8, Opcodes.ACC_PUBLIC, name, null
                    , "java/lang/Object", null);
```

# 直接内存

### 概述
- 直接内存 (Direct Memory) 并不在 *Java虚拟机规范* 中存在, 所以并不属于Java运行时的区域
- 在JDK1.4中引入了**NIO机制**, 使用了直接内存, 主要为了解决以下两个问题
1. Java堆中的对象如果不再使用需要回收, **回收**时会**影响**对象的创建和使用
2. IO操作时, 需要先把内容读入直接内存(**缓冲区**), 再把数据**复制**到Java堆中
- 使用直接内存后, 放入直接内存即可, 同时在Java堆上维护直接内存的引用, 减少了数据复制的开销, 写文件思路同理

### 使用
- 要创建直接内存上的数据, 可以使用 ByteBuffer
- 语法: `ByteBuffer directBuffer = ByteBuffer.allocateDirect(size);`
- arthas中使用memory可以查看直接内存大小, 属性名为direct
- 默认情况下, Java虚拟机对直接内存的分配存在一个默认最大size
- 如果需要手动调整直接内存的大小, 可以通过 `-XX:MaxDirectMemorySize=大小` , 单位同上
