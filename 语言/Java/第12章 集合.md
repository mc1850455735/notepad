
# 集合体系结构

- Java中整体可分为2类集合
- Collection (接口): 单列集合, 一次添加一个数据
	- List (接口): 添加的元素是有序(存取顺序), 可重复, 有索引的
		- ArrayList 实现类
		- LinkedList 实现类
		- Vector 实现类 (已淘汰)
	- Set (接口): 添加的元素是无序(存取顺序), 不可重复, 无索引的
		- HashSet 实现类
			- LinkedHashSet 实现类
		- TreeSet 实现类
- Map: 双列集合, 一次添加一对数据

# Collection集合

- 单列集合的顶层父接口, 它的功能是所有单列集合全部可以基础与使用的
- 建立Collection时, 要注意指定其存储类型
- `public boolean add(E e)` : 把给定的对象添加到当前集合中
	- 如果向List系列中添加元素, 则永远返回true, 因为允许元素重复
	- 如果向Set系列中添加元素, 如果元素不存在, 则返回true, 否则返回false, 因为集合不允许重复
- `public void clear()` : 清空集合中的所有元素
- `public boolean remove(E e)` : 把给定的对象在集合中删除
	- 因为Collection中定义的是共性的方法, 所以不存在索引删除
	- 删除成功返回true, 删除失败(集合中不存在)返回false
- `public boolean contains(Object obj)` : 判断当前集合中是否包含给定对象
	- 底层是依赖equals方法进行判断的, 如果集合中存储的是自定义对象, 那么使用contains方法前需要在javabean中重写equals方法
- `public boolean isEmpty()` : 判断当前集合是否为空
- `public int size()` : 返回集合中元素的个数/集合的长度

### 迭代器遍历

**概述**
- 迭代器不依赖于索引
- 迭代器在Java中的类是Iterator, 迭代器是集合专用的遍历方式
- Collection集合获取迭代器
	- `Iterator<E> iterator()` : 返回迭代器对象, 默认指向当前集合的0索引
- Iterator中的常用方法
- `boolean hasNext()` : 判断迭代器当前位置是否有元素
- `E next()` : 获取当前位置的元素, 并将迭代器对象移向下一个位置
	- 当前位置不存在元素时使用`next()`, 会报错`NoSuchElementException`
	- 迭代器遍历完毕后, 指针**不会复位**
	- 循环中只能用一次`next()`方法(否则可能遍历到不存在的位置)
	- 迭代器遍历时, 不能用集合的方法进行增加或删除, 否则会报错`ConcurrentModificationException` (由modCount变量记录集合被修改的次数, 如果迭代过程中, 集合修改次数发生变化, 则报错)
- `void remove()` : 从迭代器指向的collection中删除迭代器返回的最后一个元素, 从而实现迭代器遍历时的删除

**普通代码示例**
```java
public static void main(String[] args) {  
    Collection<String> collection = new ArrayList<>();  
    collection.add("aaa");  
    ...
    Iterator<String> iterator = collection.iterator();  
    while (iterator.hasNext()) {  
        String str = iterator.next();  
        System.out.println(str);  
    }  
}
```
**迭代器特性01**
```java
public static void main(String[] args) {  
    ...
    Iterator<String> iterator = collection.iterator();  
    while (iterator.hasNext()) {  
        iterator.next();   
    }  
    // 无元素异常  
    iterator.next();  
    // 迭代器遍历后不复位  
    System.out.println(iterator.hasNext());  
    // 二次遍历必须获取新的迭代器对象  
    iterator = collection.iterator();  
    System.out.println(iterator.hasNext());  
}
```
**迭代器特性02**
```java
public static void main(String[] args) {  
    ...
    Iterator<String> iterator = collection.iterator();  
    while (iterator.hasNext()) {  
        String str = iterator.next();  
        if("bbb".equals(str)) {  
            collection.remove("bbb");  // 程序报错
            it.remove(); // 正确删除方式
        }  
    }  
    System.out.println(collection);  
}
```

### 增强for遍历
- 增强for的底层就是迭代器, 是为了简化迭代器的代码书写的
- 在JDK5之后出现, 其内部原理就是一个Iterator迭代器
- 所有的单列集合和数组才能够使用增强for进行遍历
- 增强for中的变量实际上就是个第三方变量, 用来依次表示集合中的每一个数据, 对他的修改不会改变原数据

**示例**
```java
public static void main(String[] args) {  
    Collection<String> collection = new ArrayList<>();  
    ...
    for (String s : collection) {  
        System.out.println(s);  
    }  
}
```

### Lambda遍历
- 得益于JDK8开始的新技术Lambda表达式, 提供了一种更简单, 更直接的遍历集合的方式
- `default void forEach(Consumer<? super T> action)` : 结合Lambda遍历集合
- forEach接收一个Consumer接口的实现类, 该接口为一个函数式接口`FunctionalInterface`
- 其底层实现内部即为对Collection集合遍历使用Consumer接口的accept方法, accept方法的s参数依次表示集合内部的元素

**代码示例**
```java
public static void main(String[] args) {  
    ...
    // 利用匿名内部类进行遍历  
    collection.forEach(new Consumer<String>() {  
        @Override  
        public void accept(String s) {  
            // s依次表示集合中的每一个数据  
            System.out.println(s);  
        }  
    });  
    // 利用lambda表达式进行遍历  
    collection.forEach(s->{  
        System.out.println(s);  
    });  
    // 简化  
    collection.forEach(System.out::println);  
}
```

### 总结
- 迭代器: 在遍历过程中如果想要删除元素, 则使用迭代器
- 增强for & Lambda:
	- 如果仅仅想遍历, 则使用增强for或者Lambda表达式

# List集合

**特点**
- 有序: 存和取元素的顺序一致
- 有索引: 可以通过索引操作元素
- 可重复: 存储的元素可以重复

**方法**
- List继承了Collection, 拥有Collection中的所有方法, 同时多出了很多索引相关操作的方法
- `void add(int index, E element)` : 在此集合中的指定位置插入指定的元素
	- 原来索引上的元素会依次后移
- `E remove(int index)` : 删除指定索引处的元素, 返回被删除的元素
	- 注意与Collection中的remove(Object o)作区分
	- 所以如果List为Integer类型, 则会优先调用remove(int index)
	- 如果想要调用Collection的remove, 需要对整型手动装箱
	- 方法调用时优先调用实参与形参一致的方法
		- `Integer x = Integer.valueOf(1);`
		- `list.remove(x);`
- `E set(int index, E element)` : 修改指定索引处的元素, 返回被修改的元素
- `E get(int index)` : 返回指定索引处的元素

**遍历**
- 迭代器遍历
```java
Iterator<String> iterator = list.iterator();  
while(iterator.hasNext()) {  
    String str = iterator.next();  
    System.out.println(str);  
}
```
- 列表迭代器遍历
	- 属于迭代器的子接口
	- 允许使用迭代器在集合中添加元素
	- `list.listIterator()` : 获取列表迭代器
	- `add(E e)` : 将指定元素插入列表
	- `hasPrevious()` : 是否存在前一个元素
	- `previous()` : 获取前一个元素并将迭代器向前移动
```java
ListIterator<String> it = list.listIterator();  
while(it.hasNext()) {  
    String str = it.next();  
    if("bbb".equals(str)) {  
        // 迭代器插入元素  
        it.add("qqq");  
    }  
}
```
- 增强for遍历
```java
for (int i = 0; i < list.size(); i++) {  
    System.out.println(list.get(i));  
}
```
- Lambda表达式遍历
```java
list.forEach(s->System.out.println(s));
```
- 普通for遍历(因为List集合存在索引)
```java
for (int i = 0; i < list.size(); i++) {  
    System.out.println(list.get(i));  
}
```

**对比**
- 迭代器: 在遍历过程中需要删除元素, 使用迭代器
- 列表迭代器: 在遍历过程中需要添加元素, 使用列表迭代器
- 增强for遍历: 仅仅想遍历, 使用增强for或者Lambda表达式
- Lambda表达式: 仅仅想遍历, 使用增强for或者Lambda表达式
- 普通for: 如果遍历时想操作索引, 使用普通for

### ArrayList集合

**底层原理**
- ArrayList底层为数组结构
- 创建时, 首先利用空参创建的集合, 在底层创建一个默认长度为0的数组, 维护一个变量size, 存储着数组中的元素数量, 同时表示下次存入位置
- 当添加第一个元素时, 底层会创建一个新的长度为10的数组
- 存满后, 会扩容为原数组的1.5倍
- 如果一次添加多个元素, 1.5倍长度还放不下, 则新创建的数组长度以实际为准

**源码**
- 使用 `Ctrl + N` 搜索对应类的源码
- 使用 `Alt + 7 / Ctrl + F12` 查看该类的视图大纲

### LinkedList集合

**底层原理**
- 底层数据结构是双链表, 查询慢, 增删快, 但是如果操作首尾元素, 速度很快
- LinkedList本身提供了很多操作头尾元素的特有API
- `public void addFirst(E e)`
- `public void addLast(E e)`
- `public E getFirst()`
- `public E getLast()`
- `public E removeFirst()`
- `public E removeLast()`

# 泛型深入

### 基础概念

**概念**
- 泛型: 是JDK5中引入的特性, 可以在编译阶段约束操作的数据类型, 并进行检查
- 泛型的格式: `<引用数据类型>`
- 注意: 泛型**只支持引用数据类型**
- Java中的泛型实际上是一种**伪泛型**, 这个泛型只在编译时期是有效的, 即泛型只会在添加时判断类型是否符合容器的类型要求, 并在使用时将其转换为规定类型, 但是其存储在容器内部时还是使用Object进行存储
- 在Java文件中, 泛型是存在的, 但是当编译成为字节码时, 泛型就会消失, 这个处理的过程叫做泛型的**擦除**

**历史**
- 在没有泛型概念时, Java的容器存储的是Object类型, 所以可以存储任意的引用类型
- 访问时, 只能将所有元素作为其最高父类Object类使用, 即面向对象中多态的体现, 但多态的最大缺点是不能访问子类的特有功能

**优点**
- 统一数据类型
- 把运行时期的问题提前到了编译期间, 避免了强制类型转换可能出现的异常, 因为在编译阶段类型就能确定下来

**注意**
- 泛型中不能写基本数据类型
- 指定泛型的具体类型后, 传递数据时, 可以传入该类类型或者其子类型
- 如果不写泛型, 类型默认是Object

### 泛型使用

- 定义在类上的泛型, 称为**泛型类**
- 定义在方法上的泛型, 称为**泛型方法**
- 定义在接口上的泛型, 称为**泛型接口**

##### 泛型类
- 当一个类中, 某个变量的数据类型不确定时, 就可以定义带有泛型的类
- 尖括号中的 `E` 可以理解为一个记录数据类型的变量
- 调用时如果不给 `E` 赋值类型, 则默认 `E` 为 `Object` 类型

##### 泛型方法
- 当方法中形参类型不确定时, 可以使用类名后面定义的泛型 `<E>`
- 泛型方法中的类型, 当方法被调用时类型会自动进行确认
- 如果类名后面定义泛型, 类中所有方法都可以用
- 如果在方法名后面定义泛型, 则只有本方法可用

**示例**
- `E... e` : 是一种可变参数的传参方式
```java
public static <E> void addAll(ArrayList<E> list, E... e) {  
    for (E ex : e) {  
        list.add(ex);  
    }  
}
```

##### 泛型接口
- 当一个接口中, 某个数据类型不确定时, 就可以定义带有泛型的接口
- 如何使用泛型接口
	- 实现类给出具体的类型 (`public class MyArrayList2 implements List<String>{}`), 这个过程叫做 **泛型特化**
	- 实现类延续泛型, 创建对象时确定泛型类型 (`public class MyArrayList3<E> implements List<E> {}`), 这个过程叫 **泛型延续**

### 泛型继承
- 泛型不具备继承性, 但是泛型容器数据具备继承性
- 若指定了欲获取的泛型容器的类型, 则只能持有该类型的泛型容器, 即使存在某容器中的类型是所需要的泛型容器的子类, 也无法持有该容器
- 若指定了某个泛型容器的类型, 在向该容器中加入数据时, 既可以加入指定泛型类型的对象, 也可以加入该指定类型的子类对象

### 泛型通配符
- 如果对需要获取的泛型类型不确定, 但是同时对该泛型存在一定的限制 (如必须是xx的子类), 则可以使用泛型的通配符
- `<?>` 表示一个不确定的任意类型, 但是可以对此类型进行限定
- `<? extends E>` : 表示可以传递的对象是 `E` 或者其子类
- `<? super E>` : 表示可以传递的对象是 `E` 或者其父类
