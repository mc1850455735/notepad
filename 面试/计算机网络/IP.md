
# IP协议

IP ( Internet Protocol，网际协议 )。它负责解决一个核心问题：互联网中的一台设备，怎么找到另一台设备。网络通信中，需要地址表示不同机器的位置，这个地址就是 IP 地址。

## IPv4

IPv4 是第 4 版互联网协议，也是目前最早大规模普及的一代 IP 协议。IPv4 使用 32 位地址，地址总数理论上有 `2^32` 个，约 42.9 亿。IPv4 地址通常写成十进制点分格式，由 4 段组成，每段 8 位，总共 32 位。

**特点**
- 历史最久，应用最广
- 大多数网络都兼容
- 地址资源紧张
- 需要依赖 NAT 等技术缓解地址不足问题

## IPv6

**IPv6** 是第 6 版互联网协议，是为了解决 IPv4 地址不足等问题而设计的新一代 IP 协议。它使用 **128 位**地址，通常写成冒号分隔的十六进制，且支持简写规则。128 位地址总数理论上有 `2^128` 个，远超 IPv4。

**特点**
- 地址空间极大
- 设计上更适合未来互联网发展
- 减少对 NAT 的依赖
- 在路由、自动配置、安全等方面做了很多改进

## IPv4 vs IPv6

| 对比项   | IPv4         | IPv6                 |
| -------- | ------------ | -------------------- |
| 地址长度 | 32 位        | 128 位               |
| 表示方式 | 点分十进制   | 冒号分隔十六进制     |
| 地址数量 | 约 42.9 亿   | 极其巨大             |
| NAT      | 大量依赖     | 依赖较少             |
| 报文头   | 较复杂       | 更简洁固定           |
| 广播     | 支持广播     | 不支持广播，使用组播 |
| 地址配置 | 手动 / DHCP  | SLAAC / DHCPv6       |
| 地址解析 | ARP          | NDP                  |
| 发展定位 | 传统主流协议 | 新一代协议           |

## IP 版本过渡

### 双栈策略

双栈就是让设备同时支持 IPv4 和 IPv6，同时有 IPv4 地址和 IPv6 地址。通信时，系统会根据目标地址类型来决定走哪套协议：
- 如果目标支持 IPv6，就优先走 IPv6
- 如果目标不支持 IPv6，就退回 IPv4

**优点**
- 兼容性最好
- 过渡最平滑
- 不需要复杂封装或转换
- 便于逐步迁移业务

**缺点**
- 同时维护两套网络，复杂度高，运维成本高

**适用场景**：企业网络、操作系统、数据中心逐步升级到 IPv6

### 隧道策略

最常见的方法是把 IPv6 报文封装在 IPv4 网络里传输，或者反过来。适用于两端支持 IPv6，而中间网络只支持 IPv4 的情况。通过该策略，即使中间基础设施未升级到 IPv6，也能让两端 IPv6 网络互通。允许网络逐步升级到 IPv6。

**常见类型**
- 手工隧道：管理员手动配置隧道两端地址。
- 自动隧道：系统自动推导隧道端点，减少人工配置。
- GRE / IP 隧道：借助 GRE 等通用隧道机制承载 IPv6。

**优点**：不要求中间网络马上升级，可以快速打通 IPv6 孤岛，适合渐进式部署

**缺点**
- 增加封装开销，MTU 处理更复杂
- 配置和排障更复杂；
- 自动隧道方案已不太主流

**适用场景**
- 两个 IPv6 网络之间跨 IPv4 骨干互联
- 运营商或企业网络临时过渡
- 旧网络环境下测试 IPv6 连通性

### 协议转换策略

因为 IPv4 和 IPv6 报文格式不同、地址长度不同，所以让 IPv4 和 IPv6 之间通过翻译设备互通，比如 NAT64、DNS64 等协议。适合 IPv6-only 和 IPv4-only 网络互通。

IPv6 客户端发请求，中间转换设备把 IPv6 请求转成 IPv4 请求，发给 IPv4 服务器，IPv4 响应回来后，再转换成 IPv6 响应返回给客户端。

**常用协议**
- NAT64：让 IPv6-only 客户端访问 IPv4-only 服务器，中间通过 NAT64 做地址和协议转换，将 IPv6 地址转为 IPv4 地址。
- DNS64：与 NAT64 配合使用。DNS64 的作用是为 IPv6 only 的客户端捏造一个可用于访问 IPv4 only 服务端的 IPv6 地址，再由 NAT64 转为 IPv4 地址。

**优点**
- 可以让纯 IPv6 网络继续访问 IPv4 资源
- 有助于推动 IPv6-only 部署
- 适合 IPv4 地址紧张的环境

**缺点**
- 协议转换增加复杂度
- 兼容性相对比较一般
- 增加排障复杂度
- 影响端到端透明性

**适用场景**
- IPv6-only 接入网络
- 数据中心逐步去 IPv4 化

### 平稳过渡策略

**1. 双栈部署**  
让核心设备、服务器、操作系统同时支持 IPv4 和 IPv6。为最常见的方案，兼容性最好，业务可以逐步迁移。

**2. 分阶段改造**  
先改网络基础设施，再改服务器和应用，最后改终端接入。降低一次性变更风险。

**3. 隧道技术**  
如果部分网络暂时还不支持 IPv6，就用隧道把 IPv6 流量封装在 IPv4 网络中传输，用来打通过渡期链路。

**4. 协议转换**  
当 IPv6-only 和 IPv4-only 系统需要通信时，会用 NAT64、DNS64 这类转换技术保证互通。

**5. 先外围、后核心业务**  
企业通常会先让官网、公共服务、测试环境支持 IPv6，再逐步扩展到内部核心系统。

**6. 做好测试和回退方案**  
上线前会做兼容性、性能、安全测试；上线时保留 IPv4 回退能力，避免影响业务连续性。

**7. 配套改造运维和安全体系**  
包括 DNS、负载均衡、防火墙、监控、日志、ACL、漏洞扫描等，都要同时支持 IPv6。

### 过渡挑战

**现存网络结构兼容性复杂，迁移无法一刀切**
企业网络里同时存在老旧系统和新业务平台，部分系统可能只支持 IPv4，导致必须考虑使用双栈等 IP 过渡策略。然而，兼容性越复杂，过渡周期越长，管理难度也更高。

**业务连续性要求高，需避免迁移风险影响生产**
迁移过程中可能影响业务可用性，必须避免服务中断。因此需要优先考虑低风险、可回退的方案，从而影响技术推进速度。

**使用双栈策略，导致运维成本上升**
使用双栈时，需要同时维护 IPv4 和 IPv6 两套体系，意味着配置更复杂，运维人员学习成本更高，故障定位难度增加。

**地址规划和网络架构需要重新设计**
企业在过渡时通常要重新思考地址规划是否分层、是否便于路由汇总、如何统一编址各个部门地址、是否适配自动配置和未来扩展等问题，需要重构网络设计思路。

**安全体系需要同步升级**
IPv6 环境下与 IPv4 环境安全策略存在不同，安全人员的经验可能不足，从而导致IPv6 ACL 和防火墙策略不完善、对各个协议的安全理解不足等问题。

**应用系统和中间件改造成本高**
企业应用程序中可能固定依赖 IPv4 地址和协议，同时数据库连接字符串、接口配置、白名单等信息都依赖 IPv4。所以企业选择过渡策略时，还需要进行应用、数据库、中间件和外围依赖的联动升级。

**外部生态不一致，导致企业不能独立完成迁移**
外部合作伙伴可能只支持 IPv4，决定了企业往往不能只看内部条件，而要看上下游生态成熟度。生态不成熟时，只能长期保留双栈或依赖协议转换。
