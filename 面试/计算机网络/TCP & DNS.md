
# TCP 粘包拆包

## 介绍一下什么是 TCP 粘包拆包

由于 TCP 是一个面向字节流的协议, 在发送消息时, 不会理解上层语义, 只会对字节流进行发送或接受, 因此可能出现上层的单个消息被拆分成为多个包发送, 或者上层的多个消息被包装进同一个包进行发送.

为此, 使用 TCP 发送消息时, 需要采用一定的手段避免.

## 如何解决 TCP 粘包拆包问题

1. 上层用户固定每条消息的长度, 长度不足的直接补足
2. 指定一种分隔符, TCP 接收到以后按照分隔符对应用层消息进行拆分
3. 长度字段 + 消息字段. 先按照固定长度传输一个表示消息体长度的包, 再根据该信息接受后续消息字段.
4. 使用 HTTP, WebSocket, Protobuf 等具有明确结构和长度信息的协议

# TCP 拥塞控制算法

## BBR 算法

BBR (Bottleneck Bandwidth and Round-trip propagation time) 是 Google 提出的一种基于网络模型的拥塞控制算法。

他与传统 TCP Reno、CUBIC 的区别是：
- 前两者主要通过**是否丢包**判断网络是否发生拥塞并调整拥塞窗口；
- BBR 通过**估计网络的瓶颈带宽和最小往返时延**，主动控制数据发送速率和在途数据量，而不止单纯依赖丢包。

Long Fat Network (LFN，高带宽高时延网络) ，同时具有两种特征：
- Long：网络 RTT 较大；
- Fat：网络带宽高；
对于 LFN，其时延带宽积 (BDP，Bandwidth-Delay Product) 是其关键指标：
$$ BDP=Bandwidth \times RTT $$
时延带宽积决定了，要允许网络中存在多大的数据量，才不会浪费网络能力。

传统拥塞控制靠丢包增加拥塞窗口的方法在 LFN 上表现不佳。LFN 的一大特征就是高 RTT，发生一次丢包后，认为网络拥塞，窗口减半，会导致需要很长时间才可以恢复到原来的窗口大小，导致带宽利用率降低。

BBR 算法主要依靠两个指标衡量窗口大小：
- BtlBw (Bottleneck Bandwidth)：瓶颈链路带宽
- RTprop (Round-Trip Propagation time)：最小往返时延
从而得到网络的时延带宽积 BDP。
通过这两个指标，调整两个核心量，控制发送行为：
- Pacing Rate：发送数据的速度，尽可能匹配瓶颈链路带宽；
- cwnd：限制允许同时在网络中传输、尚未确认的数据量，通常围绕 BDP 设计并留有一定余量。

因此，使用 BBR，在 LFN 中，可以：
1. 提升带宽利用率，根据 BDP 保持足够的在途数据而不完全依靠丢包探测；
2. 降低对随机丢包敏感度：不像传统的丢包算法，一次随机丢包就会在 LFN 中导致大幅且长期的速率下降；
3. 减少排队延迟，避免为了探测带宽而长期填满路由器缓冲区。
