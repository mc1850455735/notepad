

# 死锁问题

MySQL 死锁的本质是：两个或多个事务分别持有对方需要的锁，并形成循环等待，导致所有事务都无法继续执行。

举个例子，比如事务 A 和 事务 B 同时对某个表进行修改。但是事务 A 修改的顺序是先修改 id = 1，再修改 id = 2；而 事务 B 则反过来。
在此基础上，如果 事务 A 修改完 id = 1 后，事务 B 修改完了 id = 2，事务 A 和 B 对这两行分别上了一个互斥锁，所以 A 就会等待 B 解锁后再加锁，而 B 也同样如此。

## 如何查找死锁

InnoDB 的自动死锁检测，核心使用的是**等待图（Wait-for Graph）+ 环检测**的方法。

每一个事务都相当于是等待图中的一个节点，而节点之间的有向边代表的是节点之间的等待关系。如果 A 等待 B，则视为 节点 A 有一个指向节点 B 的有向边。
当 InnoDB 发现途中存在环时，说明事务之间产生了循环等待的关系，也就是死锁。发现死锁以后，回滚其中一个事务来打破环。

InnoDB 会尽量选择较小的事务作为牺牲者。事务大小主要按照其插入、更新或删除的行数衡量。
