
# List、Set、Map的区别

首先从接口上，List 和 Set 都实现了 Collection 接口，属于单列集合；而 Map 属于单独的接口体系，属于双列集合。

对于 List，其存储元素存在顺序，允许重复的元素存入，同时允许按照索引下标访问。
对于 Set，其中存储的元素不允许重复；对于是否有序，主要取决于 Set 的实现方式，HashSet 无序，而 LinkedHashSet 和 TreeSet 是有序的。
对于 Map，其中存储的 key 不允许重复，而 value 是允许重复的；对于是否有序，取决于 Map 实现方式。同上。

对于 大多数 Set，其实其实现就是基于 Map，将其 value 设为 null，key 就代表了 Set 中存储的值。

值得注意的是，对于 Map，不同的实现方式对于 null 的支持程度是不同的：
- 对于 HashMap 和 LinkedHashMap，其支持 null key 和 null value，但是 null key 只能有一个 （肯定的）
- 对于 TreeMap，其支持 null value，但是不支持 null key。
- 对于 ConcurrentHashMap，其不支持 null key 以及 null value。

# ArrayList 扩容机制

- **默认初始容量**：10
- **扩容时机**：当添加元素时，如果添加元素后会导致容量不足，则会创建一个新数组进行扩容。
- **扩容幅度**：扩容到原容量的 1.5 倍。

# ArrayList 和 LinkedList 区别

两者都实现了 `List` 接口，但底层数据结构和适用场景不同。

**底层数据结构**：
ArrayList 底层基于**动态数组**，在内存中分配的是一块**连续的空间**； 
LinkedList 基于**双向链表**，每个节点通过指针连接，在内存中**不一定连续**

**性能差异**：
- **查询**：ArrayList 支持随机访问，时间复杂度为 O(1)；LinkedList 需要从头或尾遍历，时间复杂度为 O(n)。
- **插入/删除**：末尾 - 两者都很快，时间复杂度 O(1)；中间 - ArrayList 需要 O(n) 移动元素，LinkedList 插入操作本身是 O(1)，定位到指定位置需要 O(n)。

**内存占用**
ArrayList 会预留一定的空间（扩容机制），而 LinkedList 的每个节点都需要额外存储指向前驱和后继的两个指针，空间开销更大。

# 为什么 LinkedList 少用

**现代 CPU 缓存不友好**
CPU 读取数据时会有“预读”机制。因为 **ArrayList 是连续内存**，一次读取可以带出后续元素，**缓存命中率高**。而 LinkedList 的节点散落在内存各处，缓存命中率极低，导致实际运行速度远慢于 ArrayList。

**查询是高频操作**
- 在后端业务逻辑中，对集合进行遍历或根据索引获取数据的频率远高于在集合中间插入数据的频率。
