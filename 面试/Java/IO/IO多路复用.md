# 概念

### 什么是多路复用
- 多路: 指的是多个 socket 网络连接
- 复用: 指的是使用一个线程检查多个 Socket 的就绪状态
- 多路复用主要有三种技术: select, poll, epoll. epoll 是最新的, 也是目前最好的多路复用技术.

### 常见五种IO模型

##### BlockingIO 阻塞IO
- 调用 IO 后线程一直阻塞, 直到数据准备完毕并被拷贝到用户空间.
- 优点: 实现简单, 不占用 CPU. 适合规模较小的网络应用.
- 缺点: 请求IO会阻塞整个线程, 每次请求都要为其分配一个单独的线程处理, 系统开销较大. 不适合规模较大的网络应用.

##### NonblockingIO 非阻塞IO
- 线程发起 IO 后立即返回, 如果缓冲区内有数据, 则直接读取缓; 如果缓冲区内没有数据, 则到 IO 设备中读取数据并抛出异常信息, 线程不会阻塞.
- 线程在该过程中通常需要循环轮询缓冲区
- 优点: 实现难度低, 不阻塞线程, 适用并发量较小且不需要及时响应的应用
- 缺点: 轮询占用CPU资源, 不适合大量并发连接.

##### SignalDrivenIO 信号驱动IO
- 线程发起IO后, 向内核中注册一个信号处理函数后立即返回, 不阻塞
- 数据就绪时, 内核给线程发送信号进行通知. 
- 线程接收信号后, 在信号处理函数中调用IO读取数据.
- 优点: 无轮询, 不阻塞
- 缺点: 实现难度较大, 使用较少

##### AsynchronousIO 异步IO
- 线程发起 IO 后, 不阻塞直接返回, 内核负责处理整个 IO 过程.
- 内核处理完成后回调通知线程, 如果 IO 成功, 则线程直接获取到数据.
- 适合用于高性能高并发应用
- 优点: 实现真正的异步 (Proactor 模式), IO 数据不阻塞; 
- 缺点: 需要操作系统底层支持, 且开发实现的难度较大

##### IOMultiplexing 多路复用IO
- IO多路复用通过一种机制, 使一个进程可以同时监视多个描述符
- 当某个描述符就绪后, 及时通知程序进行相应的读写操作. 
- 常通过 select, poll, epoll 实现, 本质是内核监听多个文件描述符
- select, poll, epoll 本质上都是同步IO, 需要在读写事件就绪后由用户负责进行读写, 读写过程是阻塞的.

# IO多路复用
- 当前 Linux 中有 select, pselect, poll, epoll 四种 IO 多路复用机制. 与多进程和多线程技术相比, IO 复用技术最大优势是开销小, 系统无需为每个连接创建线程, 也无需维护大量线程状态, 显著降低系统开销.
- Linux 中大多数 IO 操作都是缓存 IO. 数据会先进入操作系统内核的页缓存, 再从内核缓冲区拷贝到用户空间. 这种做法数据会经过多次拷贝, 导致 CPU 与内存开销增大.
- 整体流程来看, IO分为两个阶段: 数据准备阶段 (读取数据->内核缓存); 数据拷贝阶段 (内核缓存->用户进程).
- 不同 IO 模型的差异在于这两个阶段的等待方式与处理责任不同.
