
# 类加载过程

- **加载 (Loading)**：通过类的全限定名获取**二进制字节流**，并在内存中生成一个代表该类的 `java.lang.Class` 对象。
- **验证 (Verification)**：确保字节码符合 JVM 规范，没有安全隐患。
- **准备 (Preparation)**：为类变量（`static` 修饰）分配内存并设置默认初始值。注意，此时还没执行赋值语句。
- **解析 (Resolution)**：将**常量池**内的**符号引用**（名字）替换为**直接引用**（内存地址）。
- **初始化 (Initialization)**：真正执行类构造器 `<clinit>()` 方法的过程，即执行 **静态变量赋值** 和 **`static` 代码块**。

# 双亲委派机制

当一个类加载器收到类加载请求时，它首先不会自己去尝试加载，而是**把请求委派给父类加载器去完成**。每一层都是如此，直到最顶层的启动类加载器。只有当父加载器反馈无法完成这个加载请求（找不到类）时，子加载器才会尝试自己去加载。

**为什么需要双亲委派机制**
安全性：通过双亲委派机制，所有的系统类最终都会由启动类加载器进行加载，避免了 JDK 中的系统类被用户篡改；
避免重复加载：类加载器会记录已经加载了的类，可以确保一个类在 JVM 中只被加载一次，保持程序的稳定运行。
