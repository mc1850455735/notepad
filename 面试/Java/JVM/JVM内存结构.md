- **堆**（存放对象实例）
- **方法区**（存储类信息、常量）
- **程序计数器**（线程执行位置）
- **虚拟机栈**（线程私有方法调用）
- **本地方法栈**（Native方法）


**线程共享**
- 堆

**线程私有**

# 程序计数器

- **作用**：记录当前线程执行的位置（字节码指令的地址），确保线程切换后能恢复到正确的位置。
- **特点**：
	- **线程私有**：每个线程独立存储，互不影响。
	- **唯一无 OOM 的区域**：不会抛出OutOfMemoryError。
	- **Native 方法时值为空**：执行本地方法（如 C/C++ 代码）时，计数器值为 undefined。

# 栈

## 虚拟机栈

- **作用**：存储方法调用的栈帧，每个方法从调用到完成对应一个栈帧的入栈到出栈。
- **结构**：
	- **局部变量表**：存放基本数据类型、对象引用和返回地址。
	- **操作数栈**：执行字节码指令的临时数据存储区（如中间结果）。
	- **动态链接**：指向运行时常量池的方法引用。
	- **方法出口**：记录方法返回的地址（正常返回或异常退出）。
- **异常**：
	- **StackOverflowError**：栈深度超过限制（如无限递归）。
	- **OutOfMemoryError**：扩展栈时无法申请足够内存（较少见）。
- **线程私有**：每个线程的栈独立分配。

## 本地方法栈

- **作用**：为 Native 方法（非 Java 代码，如 JNI 调用）提供栈空间。
- **特点**：
	- 与虚拟机栈类似，但服务于本地方法。
	- HotSpot 虚拟机将两者**合并**。
- **异常**：同虚拟机栈。

# 堆内存

对大多数应用程序，Java 堆都是 Java 虚拟机管理的内存中最大的一块，该内存区域的唯一目的就是**存放对象实例**，几乎所有对象实例以及数据都在该区域存放。

Java 虚拟机规范规定，Java 堆可以处于物理上不连续的内存空间当中，只要逻辑上是连续的即可。实现时，既可以是固定大小的，也可以是可拓展的。主流虚拟机堆都是可拓展的，通过参数进行配置。

如果堆中没有完成实例分配且堆无法再扩展时，会抛出 `OutOfMemory` 异常。

## 堆中对象

### 对象分配过程


new 产生的对象先放在 Eden 区，此区域存在大小限制，超过大小限制的文件直接进入老年代。

当 Eden 区填满后，在试图创建新对象时，垃圾回收器将先对年轻代进行 Minor GC，将不再被使用的对象进行销毁，再加载新的对象到 Eden 区。

将 Minor GC 后 Eden 区和 From 区中的剩余对象移动到 To 区，同时 From 区和 To 区身份互换。

每次 Minor GC 后，幸存对象年龄 + 1，当达到阈值时，将年轻代中的幸存对象移入老年代中。阈值默认为 15。

当老年代内存不足时，触发 Major GC，对老年代进行内存清理。若 Major GC 后仍无法进行对象保存，则抛出 OOM 异常。

### 对象生命周期

1. JVM 内存模型中，堆被划分为新生代和老年代。
2. 当创建对象时，对象会被优先划分到新生代的 Eden 区。
	- 此时 JVM 给对象定义一个对象年龄计数器
3. 当 Eden 区内存空间不足时，JVM 将进行 Minor GC。
	- JVM 会把存活的对象转移到 Survivor 中，对象年龄 + 1
	- Survivor 区同样也会经历 Minor GC，且每次对象年龄 + 1
4. 如果对象存活时间超过阈值，则对象被直接分配到老年代。

### 年轻代

对于新对象和未达到指定年龄的对象，存放在新生代（年轻代），年轻代是所有新对象创建的地方。年轻代被分为三个部分，其中有一个 Eden 区和两个 Survivor 区，这两个 Survivor 区互为 from 和 to。三者的默认大小比例是 `8:1:1`。

**回收流程**
- 大多数新创建的对象都存储在 Eden 内存空间内，当 Eden 空间被填满后，触发 Minor GC。
- Minor GC 会回收 Eden 区和 From 区中所有的垃圾对象，并将所有的未被回收的对象（幸存者）转移到 Survivor 区中的 to 区。最后，from 和 to 身份互换，当前的 to 区会变成新的 from 区。
- 每次进行 Minor GC，存活对象的年龄 + 1，初始为0。
- 移入老年代的情况：
	- 当对象年龄达到阈值时，将该对象存入老年代。阈值默认 15。
	- 当 Minor GC 后年轻代仍无空间存储对象，则也将对象放到老年代。

### 老年代

老年代中负责存储被长时间使用的对象，对于多轮 Minor GC 中仍然存活的对象，放入老年代。老年代的内存空间应该比年轻代更大。

通常，垃圾收集是在老年代内存满时进行的，对老年代的垃圾收集称为 Major GC，通常需要更长的时间，且只回收老年代。在 G1 垃圾回收器中，不再单独进行 Major GC，而是将其合并到 FullGC 中。

**回收流程**
- 对于大对象，直接进入老年代，这样可以避免大量数据在 Eden 区和两个 Survivor 区之间发生大量内存拷贝。
- 当老年代中空间不足，无法存放新对象时，会先尝试进行 Minor GC，尝试在年轻代中获取足够空间，如果内存空间仍不足，则触发 FullGC，对整个堆进行垃圾回收。
- 如果 FullGC 后，依然无法回收掉老年代对象，则当对象继续放入老年代时，会抛出 `OutOfMemory` 异常。

### 元空间(永久代)

元空间负责存储像一些方法中的操作临时对象等。在 Java 8 之前，该区域占用的是 JVM 内存，被称为永久代；Java 8 及之后，直接使用物理内存，称为元空间。不论是永久代还是元空间，都可以看作是对 Java 虚拟机规范中方法区的实现。

虽然在 Java 虚拟机规范中将方法区描述为堆的一个逻辑部分，但是其并不与堆的逻辑完全相同。

## GC回收概述

JVM 在进行 GC 时，并非每次都对堆内存中的所有区域进行回收，大部分时间回收都只对新生代进行。

在 Hotspot VM 的实现中，GC 按照回收区域分为两类：部分收集(Partial GC) 和整堆收集(Full GC)：
- 部分收集(Partial GC)：不完整的收集整个 Java 堆。
	- 新生代收集(Minor GC)：只对新生代进行的垃圾收集。
	- 老年代收集(Major GC)：只对老年代进行的垃圾收集。
		- 目前只有 CMS GC 会有单独收集老年代的行为。
		- 很多时候 Major GC 和 Full GC 会混合使用，需要具体判断是 Major GC 还是 Full GC。
	- 混合收集(Mixed GC)：收集整个新生代和部分老年代的垃圾收集。
		- 目前只有 G1 GC 会有该行为。
- 整堆收集(Full GC)：收集整个 Java 堆和方法区的垃圾。

## 堆内存大小设定

### 内存分配

通过 -Xmx 和 -Xms 参数，可以设定 Java 堆内存的大小。
- -Xmx：用于设定堆起始内存大小。等价于参数 
- -Xmx：用于设定堆最大内存大小。等价于参数 

如果堆内存大小超过设定的最大内存大小，就会抛出 OutOfMemory 异常。通常将堆起始内存大小和堆最大内存大小设定为相同的值，目的是为了在垃圾回收机制清理完堆后，不需要重新计算堆大小，从而提升性能。

## TLAB

### 什么是TLAB

TLAB，全称 Thread Local Allocation Buffer。其从内存模型而非垃圾回收的角度对 Eden 区进行划分，在 Eden 空间内为每个线程都分配了一个私有缓存区域。多线程同时分配内存时，使用 TLAB 可以避免一系列非线程安全问题，同时还能提升内存分配的吞吐量，因此将这种内存分配方式称为**快速分配策略**。OpenJDK 衍生出来的 JVM 大都提供了 TLAB 设计。

### 为什么要有TLAB

由于堆区是线程共享的，任何线程都可以访问堆区的共享数据；由于对象实例的创建在 JVM 中非常频繁，因此并发环境下从堆区中划分内存空间是线程不安全的；为避免多个线程操作同一地址，需要使用加锁等机制，从而影响分配速度。

尽管不是所有对象实例都在 TLAB 中分配内存，但 TLAB 是 JVM 内存分配的首选。在 JVM 中可以使用 `-XX:UseTLAB` 设置是否开启 TLAB 空间。默认情况下 TLAB 空间占 Eden 区的 1%，可以通过参数 `-XX:TLABWasteTargetPercent` 设置 TLAB 所占 Eden 区的百分比。

一旦对象在 TLAB 空间分配内存失败，JVM 就尝试使用加锁机制保证数据操作的原子性，从而直接在 Eden 区空间中分配内存。

# 方法区

## 运行时常量池

- **位置**：方法区的一部分。
- **内容**：
	- 编译期生成的字面量（如字符串常量"abc"）。
	- 符号引用（类、方法、字段的全限定名）。
- **动态性**：运行期间可添加新常量（如String.intern()）。
- **异常**：OutOfMemoryError（常量池溢出）。

## 直接内存

- **作用**：通过 ByteBuffer.allocateDirect() 分配的堆外内存，提升 NIO 性能。
- **特点**：
    - 不受 JVM 堆限制，但受系统内存影响。
    - 由-XX:MaxDirectMemorySize控制大小。
- **异常**：OutOfMemoryError（直接内存耗尽）。
