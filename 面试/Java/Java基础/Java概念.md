### 多态

#### 多态概念
多态就是**同一个行为具有多个不同表现形式的能力**。在 Java 中，多态具体指：父类引用变量可以指向子类对象。

**必要条件**：
1.  要有**继承**（或接口实现）。
2.  要有**方法重写**（Override）。
3.  **父类引用指向子类对象**（如 `Animal dog = new Dog();`）。

#### 多态分类

- **编译时多态（静态多态）**：主要通过**方法重载**（Overload）体现。在编译期，编译器就能根据参数列表确定调用哪个方法。
- **运行时多态（动态多态）**：主要通过**方法重写**（Override）体现。在编译期无法确定调用哪个方法，必须在程序运行期间根据对象的实际类型来绑定。

#### 底层实现原理

Java 虚拟机通过 **虚方法表** 来实现**动态绑定**：
1. **方法表存放位置**：在类加载的“链接”阶段，JVM 会在方法区为每个类创建一个虚方法表。
2. **内容**：表中存放着该类所有方法的实际入口地址。
3. **继承关系**：
	- 如果子类没有重写父类的方法，那么子类虚方法表里的地址指向的是父类的实现。
	- 如果子类**重写**了方法，子类虚方法表里的地址就会指向子类自身的实现。
4. **执行逻辑**：当调用 `animal.eat()` 时，JVM 会查看 `animal` 引用实际指向的对象类型，去该类的 `vtable` 中根据偏移量找到对应的函数地址并执行。

#### 成员变量 vs 成员方法

在多态中，有一句必须记住的口诀：**“成员变量看左边，成员方法看右边”**。
即父类引用调用的成员变量还是父类的，但调用的成员方法是子类的。这是因为 Java 的属性是不支持多态的，属性在编译时就已经根据引用类型绑定好了；而实例方法是动态绑定的。

## 泛型

### 基础概念

Java 的泛型是**伪泛型**。这是因为 Java 在编译期间，所有的泛型信息都会被**擦除**掉。
- **编译前**：你在代码里写 `List<String>` 或 `List<Integer>`。
- **编译后**：在生成的字节码中，它们都会变成原始类型 `List`。

### 处理逻辑
- **类型检查**：在**编译期**，编译器会先检查你插入的对象是否符合对应类型。
- **自动插入转型代码**：在**获取元素**时，编译器会自动在字节码中插入 `checkcast` 指令（强制类型转换），将 `Object` 转回 `String`。
- **保留原始类型**：如果**泛型有限制**（如 `List<? extends Number>`），擦除后会变成 `Number` 而不是 `Object`。

### 类型擦除设计初衷

Java 1.5 引入泛型时，为了让已有的旧代码（没有泛型）能在新的 JVM 上无缝运行，设计者决定不改变 JVM 的类加载机制，而是通过编译器手段来模拟泛型。

### 类型擦除的后果

- **无法使用基本类型**：不能写 `List<int>`，只能用包装类 `List<Integer>`，因为擦除后 Object 无法持有 int。
- **通过反射可以绕过检查**：虽然编译期有检查，但如果你通过**反射**获取 `List<String>` 的 `add` 方法，你可以往里存入一个 `Integer`，因为运行时的 `List` 只是个 `Object` 容器。
- **泛型类无法实例化**：不能 `new T()`。
- **无法进行 `instanceof` 判断**：`if (list instanceof List<String>)` 是违法的。

# Object 类

## 方法

- toString()：返回对象的字符串表示形式
- equals()：判断两个对象是否“逻辑相等”
- hashCode()：返回对象的哈希码（用于哈希表存储）
- getClass()：返回对象的运行时类（Class对象）
- clone()：创建并返回对象的副本（浅拷贝）
- wait()：让当前线程进入等待状态（需在同步块中使用）
- notify() / notifyAll()：唤醒等待该对象锁的线程（需在同步块中使用）
- finalize()：对象被垃圾回收前调用（已废弃）
- registerNatives()：本地方法，用于注册本地方法实现（JVM 内部使用）

## == 和 equals() 的区别

- **`==`**
	- 对于**基本数据类型**，比较的是**值**是否相等。
	- 对于**引用类型**，比较的是两个对象在内存中的**地址**是否相同（即是否指向同一个对象）。
- **`equals()`**
	- 它是 `Object` 类的方法。如果不重写，默认实现就是使用 `==` 比较地址。
	- 通常我们需要重写它来比较两个对象的**内容**，例如 `String`、`Integer` 等类都重写了此方法。

## 为什么重写 equals() 必须也重写 hashCode()

`hashCode` 通常规定，如果两个对象根据 `equals()` 方法比较是相等的，那么它们的 `hashCode()` 也必须产生相同的整数结果。

两个对象 `hashCode()` 相同，不代表 `equals()` 也相同；但是如果两个对象 `equals()` 相同，那么 `hashCode()` 一定也相同。

如果不重写，可能出现以下问题：
- **在集合类中失效**：集合通过 hashCode() 和 equals() 配合完成逻辑判断，如果 equals() 和 hashCode() 结果不同，可能导致集合类不可用。
- **逻辑矛盾**：HashMap 通过 hashCode 决定存储位置，如果两个 equals 的对象存储位置不同，不符合 HashMap 中相同元素存储位置一定相同的逻辑；同时可能导致 HashMap / HashSet 中存储重复元素。
