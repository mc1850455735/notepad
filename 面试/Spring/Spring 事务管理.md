
Spring 事务底层基于事务管理器（如DataSourceTransactionManager）统一接口，兼容不同持久层技术，确保**数据一致性和原子性**。

Spring 管理事务的方式主要分为 **编程式事务** 和 **声明式事务** 两大类，核心区别在于事务控制逻辑与业务代码的耦合程度。

声明式事务通过 `@Transactional` 注解或 XML 配置简化事务控制，支持**事务传播行为、隔离级别及回滚规则**。

# 编程式事务

通过手动编写代码**显式控制**事务的开启、提交、回滚，灵活性高但侵入性强，适合需要**细粒度控制**事务的特殊场景（如复杂条件判断或嵌套事务）。  
Spring 提供了两种编程式事务的实现方式：

#### 基于PlatformTransactionManager接口（底层方式）

直接调用 Spring 事务管理器的 API 控制事务，需要手动处理事务状态。  
**步骤**：
- 通过 PlatformTransactionManager 获取事务状态（TransactionStatus）；
- 执行业务逻辑；
- 根据结果调用 commit() 提交或 rollback() 回滚。

#### 基于TransactionTemplate模板类（简化方式）

TransactionTemplate 是 Spring 提供的模板工具类，封装了PlatformTransactionManager 的底层操作，通过**回调函数**简化事务代码，避免手动处理 TransactionStatus。

# 声明式事务

通过 **AOP（面向切面编程）** 自动管理事务，事务控制逻辑与业务代码解耦，是 Spring 推荐的**主流方式**。 声明式事务的实现方式分为 **注解驱动** 和 **XML 配置** 两种。

#### 注解方式（@Transactional）

通过在方法或类上添加 `@Transactional` 注解，Spring 自动生成 AOP 代理，在方法执行前后自动管理事务（开启、提交、回滚）。

- 作用范围：可标注在类（所有方法生效）或方法（仅当前方法生效）上；
- 常用属性：
	- propagation：事务传播行为（默认 `REQUIRED`）
	- isolation：事务隔离级别（默认 `DEFAULT`，使用数据库默认）
	- rollbackFor：指定需要回滚的异常类型（默认仅回滚 `RuntimeException` 和 Error）
	- readOnly：标记事务为只读（优化数据库性能）
	- timeout：事务超时时间（秒）

#### XML 配置方式（传统方式）

通过 Spring 配置文件定义事务规则，适用于不使用注解的场景（如遗留系统）。核心是结合 `<tx:advice>`（事务通知）和 `<aop:config>`（AOP 配置），指定哪些类/方法应用事务。

# 编程式事务与声明式事务的对比与适用场景

| 方式         | 优点              | 缺点                 | 适用场景            |
| ---------- | --------------- | ------------------ | --------------- |
| 编程式事务      | 灵活控制事务细节（如条件回滚） | 代码侵入性高，重复代码多       | 复杂事务逻辑          |
| 声明式事务（注解）  | 无代码侵入，简洁易用      | 依赖 AOP 代理，无法控制所有细节 | 大多数业务场景         |
| 声明式事务（XML） | 配置集中，适合无注解的旧系统  | 配置繁琐，维护成本高         | 遗留系统或需要集中管理事务规则 |

# Spring事务的原理和实现方式

Spring 通过 AOP 代理拦截 `@Transactional` 方法，在方法执行前开启或加入事务，执行成功后提交，发生符合回滚规则的异常时回滚。

# 介绍一下Spring声明式事务的传播机制

Spring 共有 7 种事务传播方式，用于决定一个事务方法被另一个事务调用时，事务的处理方式；
- `REQUIRED`（默认）：当前方法存在事务则加入，不存在事务就创建一个事务并运行；
- `REQUIRES_NEW`：不管当前方法是否存在事务，都创建一个新事务；
- `SUPPORTS`：当前方法存在事务则加入，不存在事务则直接运行；
- `NOT_SUPPORT`：当前方法不能存在事务，如果有事务则挂起等待；
- `MANDATORY`：当前方法必须存在已有事务，如果不存在则直接报错；
- `NEVER`：不允许有事务，如果存在事务则直接报错；
- `NESTED`：在当前事务内部创建一个子事务，用 Savepoint 实现，子事务回滚不影响外层。
