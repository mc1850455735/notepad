
# 什么是 0 拷贝，在 Java 或 Linux 中是通过哪个系统调用实现的

在传统的数据复制方案中，存在两次 CPU 数据复制。
其大致的数据流转过程是：磁盘 -> CPU 内核态 -> 用户空间(用户阅读并修改) -> CPU 内核态 -> 磁盘。
在这个过程中，如果只需要搬运数据，而不需要对数据进行修改的话，两次 CPU 复制，即 `CPU 到用户态` 和 `用户态到 CPU` 就是不需要的，是复制的主要瓶颈。

零拷贝是通过减少或绕过内核空间和用户空间之间的数据复制，让数据直接在内核中完成传输，降低 CPU 开销和上下文切换次数，从而来提高 IO 性能。

其常见的应用场景主要是，需要高效的将文件从一个场景复制到另一个场景，中间不需要用户进行查看和修改。如 Web 文件传输、消息队列、Java NIO 网络传输等场景。

在 Linux 中，常见的零拷贝命令是 sendfile，该命令允许将文件直接传输到 Socket 中，而不需要将文件先读取到用户空间。

在 Java 中，通常通过 NIO API 调用操作系统提供的零拷贝系统调用。最典型的是 `FileChannel.transferTo()` 和 `transferFrom()`。

`mmap` 是 Linux 提供的**内存映射机制**。它的作用可以理解为把一个文件的一段内容，映射到进程的虚拟地址空间中，让程序可以像访问内存一样访问文件。

mmap 并不是调用后立刻把整个文件读入内存，mmap 指令只是建立了虚拟地址到文件之间的映射关系。
Java NIO 对 mmap 的封装主要是`MappedByteBuffer`。

`splice()` 与 `sendfile()` 的区别比较明显，主要是 sendfile 主要是将数据从一个文件复制到另一个文件，而 splice 更类似于数据在文件描述符之间的转发。
