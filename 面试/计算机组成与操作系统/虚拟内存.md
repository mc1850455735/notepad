
# 什么是虚拟内存？为什么需要虚拟内存？

虚拟内存是操作系统提供的一种内存管理机制，它为每个进程提供独立的虚拟地址空间，通过页表将虚拟地址映射到实际的物理内存。

进程 A 与 B 即使访问相同的内存地址，其通过页表映射后的真实物理地址也与进程使用的地址不同。通过这种方式，每个进程都可以认为自己拥有独立的内存空间，而不需要关心数据实际存储在哪个位置。

之所以需要虚拟内存这个机制，主要有以下四个原因：
1. 内存隔离与保护，每个进程都有自己的虚拟地址空间和页表，提高了安全性和稳定性；
2. 简化内存管理，程序不需要关心物理内存的实际位置；
3. 提高物理内存利用率，允许操作系统按需分配内存，不需要立即给齐程序的要求内存；
4. 支持共享内存，只需要将不同进程的虚拟地址映射到相同的物理页；
5. 借助虚拟内存，还可以结合磁盘上的交换空间，在物理内存不足时将部分内存页唤出。

# 虚拟地址如何转换为物理地址？什么是缺页异常？

**虚拟地址转换**
虚拟地址由虚拟页号与页内偏移组成。虚拟页号用于查询当前虚拟页对应哪一块物理页，页内偏移表示数据的具体地址。

具体来说：
1. CPU 首先发出虚拟地址，MMU 将其拆分为虚拟页号和页内偏移；
2. 优先查询 TLB，如果命中则直接返回物理页框号；
3. 如果 TLB 未命中，则通过页表，查询虚拟页号和物理页号之间的映射关系；
4. 如果映射有效，得到物理页框号，并将查询结果缓存到 TLB；
5. 将物理页框号与实际页内偏移结合，得到实际的物理地址。

**缺页异常**
缺页异常是 CPU 查找虚拟地址时，发现对应页面没有有效的物理映射，或发生访问权限违规等情况，所触发的一种异常。

缺页异常的处理流程如下：
1. CPU 访问某个虚拟地址，MMU 将其拆分为虚拟页号和页内偏移；
2. MMU 发现页表中没有可用的映射，触发缺页异常；
3. CPU 切换到内核态，进入缺页异常处理程序；
4. 内核检查该地址是否属于合法的内存区域；
5. 若合法，操作系统建立对应的物理页映射；如果页面已经换出，则需要从磁盘换回；
6. 根据建立的物理页映射更新页表，必要时更新或失效相关 TLB；
7. 返回用户态，重新执行导致缺页的指令。
