
Redis 主要支持 String、Hash、List、Set、SortedSet (ZSet) **5种** 基础数据结构；同时还支持 BitMap、HyperLogLogs、GEO、Stream 等多种针对特定场景的数据结构。

对 Redis 来说，所有的 key 都是字符串。我们在谈基础数据结构时，讨论的是存储值的数据类型，

| 结构类型      | 结构存储的值                | 结构的读写能力                                                              |
| --------- | --------------------- | -------------------------------------------------------------------- |
| String字符串 | 可以是字符串、整数或浮点数         | 对整个字符串或字符串的一部分进行操作；对整数或浮点数进行自增或自减操作；                                 |
| List列表    | 一个链表，链表上的每个节点都包含一个字符串 | 对链表的两端进行push和pop操作，读取单个或多个元素；根据值查找或删除元素；                             |
| Set集合     | 包含字符串的无序集合            | 字符串的集合，包含基础的方法有看是否存在添加、获取、删除；还包含计算交集、并集、差集等                          |
| Hash散列    | 包含键值对的无序散列表           | 包含方法有添加、获取、删除单个元素                                                    |
| Zset有序集合  | 和散列一样，用于存储键值对         | 字符串成员与浮点数分数之间的有序映射；元素的排列顺序由分数的大小决定；包含方法有添加、获取、删除单个元素以及根据分值范围或成员来获取元素 |

### String

Redis 的 String 类型采用 **SDS ( 简单动态字符串 )** 实现，结构包含长度、空闲空间和字符数组。支持**二进制安全数据存储**，同时会自动预分配空间减少内存重分配次数，通过 len 字段实现 O(1) 时间复杂度获取长度，采用惰性空间释放策略优化性能。

String 类型是二进制安全的，意思是 Redis 的 String 可以包含任何数据。如数字，字符串，jpg图片或者序列化的对象。

#### 概念

String 是 Redis 中最基本的数据类型，可存储文本、整数或二进制数据。String 最大容纳数据量为 **512MB**。

Redis 的 String 类型底层实现主要依赖于 SDS ( Simple Dynamic String，简单动态字符串 ) 数据结构。SDS 是 Redis 对 C 语言原生字符串的改进版本，专门设计用于解决原生字符串的性能、安全性和灵活性缺陷。

#### SDS核心设计

SDS 的核心思想是通过**分段优化内存占用**的方式改进字符串的存储，Redis 根据字符串长度选择**不同的 SDS 类型**以减少内存浪费。
- sdshdr5：长度小于 32 字节的极短字符串。
- sdshdr8：长度小于 256 字节。
- sdshdr16：长度小于 64KB。
- sdshdr32：长度小于 4GB。
- sdshdr64：极长字符串（理论上支持到 512MB）。

#### SDS结构
```java
struct __attribute__((__packed__)) sdshdrXX {
    uintXX_t len;        // 字符串实际长度（已用字节数） 
    uintXX_t alloc;      // 字符串总分配空间（不包括头和空终止符） 
    unsigned char flags; // 低 3 位表示类型，高 5 位预留 
    char buf[];          // 实际存储的字符数组（兼容 C 字符串） 
};
```

#### SDS优势

1. O(1) 时间复杂度获取字符串长度信息
	- 直接使用 len 字段记录字符串长度，时间复杂度为 O(1)
2. 二进制安全
	- 使用 len 明确记录数据长度，支持存储任意格式的二进制数据。
3. 自动扩容与内存预分配
	- **扩容策略**：当字符串需要分配时，SDS 会额外分配空间，减少内存重分配次数。
	- **惰性释放**：缩短字符串时不直接释放多余内存，而是更新 len 字段，后续可复用空间。
4. 兼容 C 字符串函数
	- buf 数组依然以 0 结尾，可以直接使用 C 语言的字符串库函数。

#### 编码方式优化
- **int编码**：当字符串表示整数时，直接以 64 位长整型存储，避免字符串解析开销。
- **embstr编码**：当字符串长度 <= 44 字节时，Redis 会将 SDS 与对象元数据连续存储在同一块内存中。这种方式可以减少内存碎片，提高缓存局部性。
- **raw编码**：当字符串长度 > 44 字节，SDS 与对象元数据分开存储，通过指针关联。这种方式适合大字符串存储。

#### 应用场景
- 缓存：把常用信息，字符串，图片或者视频等信息放到 Redis 中，Redis 作为缓存层，mysql做持久化层，降低mysql的读写压力。
- 计数器：Redis是单线程模型，一个命令执行完才会执行下一个，同时数据可以一步落地到其他的数据源。
- 分布式锁：通过 Setnx 实现的基于 Redis 的分布式锁。
- Session：常见方案 Spring Session + Redis 实现 Session 共享。

### List

#### 概念

List 是双向链表，支持队列和栈操作。使用 List 结构，可以实现消息排队功能，如微博 TimeLine；或者利用 List 的 PUSH 操作，将任务存放在 List 中，然后工作线程再用 POP 操作将任务取出后进行执行。

#### 应用场景
- TimeLine：有人发布微博，用 lpush 加入时间轴，展示新的列表信息
- 消息队列：结合 LPUSH + BRPOP。

### Set

Redis 中 Set 为无序唯一集合，支持交并差运算。Redis 中 Set 是通过哈希表实现的，所以添加、删除、查找的复杂度都是 O(1)。

**应用场景**
- 标签系统：给用户添加标签，或者用户给消息添加标签。
- 共同好友 / 关注：通过**交集运算**确认两个人的共同好友 / 关注
- 点赞、点踩、收藏等，可以通过 Set 进行实现。

### Sorted Set

Sorted Set (ZSet) 是一种具有唯一成员 + 可排序分值的数据结构。其中每一个元素关联一个 score 用于排序，元素唯一但分数可重复。
Sorted Set 支持按 score 排序，按 score 或 rank 查询，查询前N名以及增减 score 后自动保持排序。

Redis 中 Sorted Set 底层由两种数据结构组成：**哈希表 Hash** 和 **跳跃表 SkipList**，通过同时维护两份数据结构实现高效排序。

哈希表存储成员到分数的映射以支持快速查询，跳跃表按分数排序成员以支持高效的范围操作。两者结合确保插入、删除和查询的时间复杂度为 `O(log n)`

Sorted Set 中数据量小时使用**压缩列表 Ziplist** 优化内存。

#### 底层数据结构

ZSet 根据元素数量和大小动态选择编码方式。

当元素数量较少且元素较小时使用 ziplist；在不太影响时间的情况下，可以通过紧密内存分布，减少内存碎片；
当数据量较大时切换到 跳跃表 ( skiplist ) + 哈希表 (dict)，支持高效查询和范围操作。

**编码切换 (ziplist 转 skiplist) 条件**
- 元素数量超过参数 zset-max-ziplist-entries (默认 **128**)。
- 任意元素的成员长度超过参数 zset-max-ziplist-value (默认 **64 字节**)

#### 跳跃表 + 哈希表实现

当数据量较大时，Zset 使用两种结构协作：
- **跳跃表（skiplist）**：维护元素按 score 排序，支持快速范围操作。
- **哈希表（dict）**：维护 member -> score 的映射，支持 O(1) 时间判断元素是否存在。

#### 跳跃表的核心设计

**层数随机生成**
- 新节点的层数由 **幂次定律**（power law）随机确定，层数越高概率越低。
- 确保跳跃表的平衡性，避免退化成链表，查询效率接近 O(log n)。

**范围查询优化**
- 支持快速区间遍历，无需中序遍历（平衡树需要）。

#### 为什么选择跳跃表

**相比平衡树，跳跃表有以下优点**
- **实现简单**：跳跃表的插入/删除只需调整相邻指针，无需复杂的旋转操作。
- **范围查询高效**：跳跃表天然有序，区间遍历时间复杂度为 O(log n + m)（m 为结果数量），优于平衡树的 O(m log n)。
- **内存更友好**：跳跃表通过随机层数减少内存开销，平衡树需存储多个指针。
