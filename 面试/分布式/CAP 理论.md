
# 什么是分布式的 CAP 理论？

CAP，即 Consistency 一致性，Availability 可用性，Partition Tolerance 分区容错性，这三个指标在分布式系统中无法同时被满足。

CAP 理论中的 Consistency 一致性表示的是**强一致性**而不是最终一致性，也就是说，一次写入成功后，后续读取必须立刻就能读到最新的数据。

**一致性**，指分布式系统的多个副本之间的数据保持一致，即在一个副本上的写操作会立即同步到其他所有副本，所有副本数据都是最新的，保持**强一致性**。

**可用性**，指系统在任何时候都能够对外提供服务，即系统可以**随时的响应用户的请求**，不会因为节点故障等原因导致服务中断。

**分区容错性**，指的是系统在出现网络分区，即各个节点失去联系时，仍然可以继续工作，保证服务的可用性和数据的一致性。

CAP 指出，三个指标在同一个分布式系统中最多只能满足 2 个，无法同时满足 3 个。比如，当出现网络分区时，为了保证一致性，必须停止对外服务，从而失去可用性；而如果想要保持可用性，就必须接受节点之间数据可能存在的不一致。

因此，在分布式系统中，需要根据具体场景选择使用 CP(优先保证节点之间数据的强一致性) 还是 AP(优先保证对外服务的可用性)，P 是不受控制出现的，不论 AP 还是 CP 必须有 P。

以 Redis 为例。对于 Redis 主从复制的场景，当 Master 和 Replica 之间发生网络分区时，类似：
- 主节点 A 无法与从节点 B 之间相互通信；
- 客户端1 可以与 A 通信；
- 客户端2 可以与 B 通信。
此时假设，客户端1 向 A 中写入了一条数据。

如果 Redis 选择使用 AP，为了保证可用性，系统会允许二者分别响应。但在这种情况下，主从节点之间的数据是不一致的，客户端2 将会读到旧数据。

如果 Redis 选择使用 CP，为了保证强一致性，必须采用某种限制策略，比如：Master 节点在网络断开后暂停接受新的写入操作，只能读取；Replica 节点在网络断开后拒绝接受无法保证最新数据的读取。

真实情况下，不存在完全的 AP 或者 CP，而是在一致性与可用性之间进行权衡。以 Reids 为例，Redis 默认采用异步主从同步，即使发生网络分区，也允许从节点读取未同步的数据，这一点不满足 Consistency 强一致性的要求；同时，Redis Cluster 或 Redis Sentinel 在发生网络分区后，也会限制某些节点的写入等操作，不保证所有故障节点的可用。
