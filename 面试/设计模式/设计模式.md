# 创建型模式

本质是改变类的创建模式，对类的实例化过程进行抽象。
特点是封装了具体类的信息，隐藏了类的实例化过程。

## 单例模式

### 概念

单例模式，Singleton。其目标是为了保证某个类在进程内只有一个实例，并提供一个全局可访问点来获取该实例。适合系统内相同类型对象只希望出现一次，否则可能引发资源冲突、状态不一致、重复开销等的情况。

### 实现

单例模式实现类图如下所示。使用一个私有构造函数，一个私有静态变量和一个公有静态函数实现。私有构造函数保证了不能通过构造函数来创建对象实例，只能通过公有静态函数返回唯一的私有静态变量。

![[面试/设计模式/Inbox/Pasted image 20260123141814.png]]

#### 懒汉式 - 线程不安全

在该实现中，用于存储单例对象的私有静态变量被延迟实例化，只在获取单例对象的过程中判断是否需要初始化单例对象。这样做的好处是，如果没有用到该单例类，就不会实例化对象，从而节约资源。

该实现在多线程环境下是不安全的，如果多个线程在获取单例对象的过程中，同时发现无单例对象，从而进入初始化流程，会导致多次实例化单例类。

#### 懒汉式 - 线程安全

对整个获取单例对象的方法进行加锁，那么同一个时间点就只有一个线程可以进入该方法，从而避免了多次实例化单例对象的问题。

但是使用加锁的方法，当一个线程进入方法后，其他试图进入该方法的线程都必须等待，因此会造成一定程度上的性能损耗。

#### 饿汉式 - 线程安全

线程不安全问题主要是由于单例对象被多次实例化，如果采用直接实例化的方法，就不会产生线程不安全的问题。

但直接实例化的方法同时也丢失了延迟实例化带来的节约资源的好处。

#### 双重校验锁

类似线程安全的懒汉式单例模式实现。单例对象只需要被实例化一次，之后可以直接使用。因此加锁操作只需要对实例化部分进行，只有当单例对象没有被实例化时，才需要进行加锁。

之所以需要双重校验，是因为多个线程可能同时发现单例对象不存在，并依次等待锁。当其中一个线程成功实例化单例对象后，必须阻止其他获取到锁的线程对单例对象进行重复实例化。也就是需要使用两个 if 语句进行双重校验。

使用双重校验锁时，为保证多线程下的线程安全，应对单例对象使用 volatile 关键字避免指令重排。在 Java 中，对象实例化过程分为三步：分配内存空间、初始化对象、将引用指向分配的内存地址。使用 volatile 可以禁止 JVM 进行指令重排，避免出现以下情况：

线程A由于指令重排，出现先将引用指向内存地址再初始化对象的情况。然而线程B在发现单例对象不为空后直接使用该单例实例，但是由于指令重排序，此时实例可能未完成初始化，导致出现问题。

#### 静态内部类

在对应的单例类中定义静态内部类，该静态内部类中负责存储单例实例。当单例类加载时，静态内部类不会被加载到内存中，只有使用对应方法获取实例，从而触发静态类实例化时，对应单例实例才会被初始化。

通过该方法，不仅具有了延迟初始化的优点，同时还由虚拟机本身提供了对线程安全的支持。

#### 枚举类型实现

枚举类型是单例模式的最佳实践。其实现方式简单，且面临复杂序列化或反射攻击时，仍可以防止多次实例化。

如果不适用枚举方式实现单例模式，可能会出现反射攻击，通过 `setAccessible()` 方法可以将私有构造函数访问级别改为 public，从而通过调用构造函数实例化对象，如果要防止这种攻击，就必须在构造函数中添加防止实例化多个对象的代码。

因此，解决序列化和反射攻击很麻烦，而枚举实现不会出现这两种问题，因此枚举实现是单例模式的最佳实践。

### 使用场景

- Logger Classes
- Configuration Classes
- Accessing resources in shared mode
- Factories implemented as Singletons

## 简单工厂

### 概念

简单工厂，Simple Factory。简单工厂的目的是在创建一个对象时，不向客户暴露内部细节，而是提供一个用于创建对象的通用接口。

简单工厂并不是一种设计模式，而更像一种编程习惯。他把实例化的操作放到一个类中，这个类被称为简单工厂类。让简单工厂类来决定应该使用哪个具体子类进行初始化。

通过这种方式，可以实现客户类和具体子类之间的解耦，客户端不再需要知道有哪些子类以及需要实例化哪个子类，只需要由工厂类进行决定。客户类往往有多个，如果不进行解耦，那么所有的客户端都必须知道所有具体子类的实现细节。且子类发生改变时，所有的客户端都必须进行修改。

## 工厂方法模式

### 概念

工厂方法模式，Factory Method。在简单工厂中，创建对象的是另一个类，而在工厂方法中，由子类负责创建对象。

定义一个创建对象的接口，但由子类决定要实例化哪个类。通过工厂方法将对象实例化操作延迟到子类。通常用于客户端不希望依赖具体产品类，需要方便的扩展新产品类型，对象创建逻辑复杂，或者经常变化的情况。

-   javax.xml.bind.JAXBContext

## 抽象工厂模式

抽象工厂模式，Abstract Factory。与工厂方法不同的是，工厂方法只生成一种产品，而抽象工厂生产一整套相互关联的产品。工厂方法模式抽象的是工厂方法，而抽象工厂模式抽象的是工厂整体。

# 结构型模式

## 适配器模式

适配器模式 Adapter 将一个类的接口转为客户希望的另一个类的接口，使原本由于接口不兼容而不能一起工作的类可以协同工作。

## 桥接模式

桥接模式 Bridge ，通过将实现和抽象分离，使他们都可以独立变化。核心思想在于用**组合替代继承**，把抽象和实现通过桥梁连接起来。

当一个类存在两个或多个独立变化的维度时，如果使用继承，会导致类数量爆炸、结构僵化、难以扩展。通过将继承改为组合，避免了过度复杂的继承关系和过多的类数量。

**适用场景**
-   类存在多个独立变化的维度
-   不希望使用多层继承
-   需要在运行时切换状态

**常见例子**
-   图形 × 颜色
-   操作系统 × 驱动
-   消息类型 × 发送渠道

**示例**
```java
// 实现接口
interface Color {
    void applyColor();
}

// 具体实现
class Red implements Color {
    public void applyColor() {
        System.out.println("Red color");
    }
}

// 抽象
abstract class Shape {
    protected Color color;

    protected Shape(Color color) {
        this.color = color;
    }

    abstract void draw();
}

// 扩展抽象
class Circle extends Shape {
    public Circle(Color color) {
        super(color);
    }

    void draw() {
        color.applyColor();
        System.out.println("Draw Circle");
    }
}
```

## 装饰模式

装饰者模式 Decorator 为对象动态添加功能。

## 外观模式

外观模式 Facade，提供了一个统一的接口，用来访问子系统中的一群接口，从而让子系统更容易使用。

## 组合模式

组合模式 Composite，将对象组合成树形结构来表示“部分-整体”层次关系，允许用户以相同的方式处理单独对象和组合对象。使当前用户不必关心当前操作的是一个对象还是一组对象，忽略组合和个体之间的区别。

![[面试/设计模式/Inbox/Pasted image 20260202160632.png]]

**示例**
```java
// 抽象组件
abstract class Component {
    abstract void operation();
}

// 叶子节点
class Leaf extends Component {
    public void operation() {
        System.out.println("Leaf operation");
    }
}

// 组合节点
class Composite extends Component {
    private List<Component> children = new ArrayList<>();

    public void add(Component component) {
        children.add(component);
    }

    public void operation() {
        for (Component c : children) {
            c.operation();
        }
    }
}

```

## 享元模式

Flyweight，利用共享的方式来支持大量细粒度的对象，从而减少内存消耗，提高系统性能。要求这些对象的一部分内部状态是相同的。

其核心思想是将对象的状态分为可共享的内部状态和不可共享的外部状态，内部状态由享元对象保存并共享，外部状态由客户端在使用时传入。

## 代理模式

Proxy，为另一个对象提供一个替身或占位符以控制对这个对象的访问。

**类型**
- **远程代理**：控制不同地址空间中的远程对象的访问，负责将请求及其参数进行编码，并向不同地址空间中的对象发送已经编码的请求。
- **虚拟代理**：当需要创建开销很大的对象，它可以缓存实体的附加信息，以便延迟对它的访问，例如在网站加载一个很大图片时，不能马上完成，可以用虚拟代理缓存图片的大小信息，然后生成一张临时图片代替原始图片。
- **保护代理**：按权限控制对象的访问，它负责检查调用者是否具有实现一个请求所必须的访问权限。
- **智能代理**：取代了简单的指针，它在访问对象时执行一些附加操作：记录对象的引用次数；当第一次引用一个持久化对象时，将它装入内存；在访问一个实际对象前，检查是否已经锁定了它，以确保其它对象不能改变它。

# 行为型模式

## 模板方法模式

模板方法模式 Template Method，在一个方法中定义一个算法的骨架, 而将一些步骤延迟到子类中. 模板方法使得子类可以在不改变算法结构的情况下, 重新定义算法中的某些步骤。

![[面试/设计模式/Inbox/Pasted image 20260205102604.png]]

## 命令模式

命令模式 Command，将命令封装成对象，以便使用命令来参数化其它对象，或者将命令对象放入队列中进行排队，或者将命令对象的操作记录到日志中，以及支持可撤销的操作。

## 迭代器模式

迭代器模式 Iterator，提供一种顺序访问聚合对象元素的方法，并且不暴露聚合对象的内部表示。

## 观察者模式

观察者模式 Observer，在对象之间定义一对多的依赖, 这样一来, 当一个对象改变状态, 依赖它的对象都会收到通知, 并自动更新。

## 中介者模式

中介者模式 Mediator，使用中介者模式来集中相关对象之间复杂的沟通和控制方式。

## 状态模式

状态 State。允许对象在内部状态改变时改变它的行为，对象看起来好像修改了它所属的类。

## 策略模式

策略模式 Strategy，定义了算法族，分别封闭起来，让它们之间可以互相替换，此模式让算法的变化独立于使用算法的客户。

## 责任链模式

责任链模式 Chain of Responsibility，使多个对象都有机会处理请求，从而避免请求的发送者和接收者之间的耦合关系。将这些对象连成一条链，并沿着这条链发送该请求，直到有一个对象处理它为止。

## 访问者模式

访问者模式 Visitor，当你想要为一个对象的组合增加新的能力, 且封装并不重要时, 使用访问者模式。

## 备忘录模式

Memento，在不违反封装的情况下获得对象的内部状态，从而在需要时可以将对象恢复到最初状态。

## 解释器模式

Interpreter，使用解释器模式为语言创建解释器，通常由语言的语法和语法分析来定义。
