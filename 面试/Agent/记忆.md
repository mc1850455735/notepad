
# 短期记忆和长期记忆

短期记忆是 **Agent 的工作内存**，长期记忆是 **Agent 的知识库**。

**短期记忆 (STM)**
短期记忆是 Agent 在当前会话或任务会话中暂时保留的信息，通常只用于上下文，生命周期短，用于用于保持上下文一致性、连续性推理，并保存临时信息。

短期记忆通常存储在内存或上下文对象中，适合处理实时交互和当前任务，但不能跨会话保留信息。

**长期记忆 (LTM)**
长期记忆负责存储 Agent 跨对话、长期有效的信息，承载用户偏好、知识库、历史行为、规则模板等。

长期记忆通常存储在 关系型数据库（MySQL、PostgreSQL等）、向量数据库（pgvector）、文件（Json、csv文件）或 非关系型数据库（Redis、MongoDB）中。

# 什么是记忆冲突，如何解决记忆冲突

当Agent 在长期记忆、短期上下文、用户最新输入、工具返回结果、数据库记录等多种信息来源之间，遇到了不一致、互相矛盾或版本过期的信息，即为发生了记忆冲突。

**常见冲突类型**
1. 因用户观念或任务变化引起的新旧任务冲突。此时，不应直接使新信息覆盖旧信息，而是使新信息优先，保留旧信息变化到新信息的过程。
2. 用户显式纠正导致的冲突，此时应以用户的显式纠正为根本，直接更新记忆，因为用户的显式输入拥有置信度的最高优先级。
3. 多信源冲突。Agent 可能通过多个来源获取信息，如长期记忆、用户输入、新闻等，而信源之间可能会出现冲突。此时应根据消息来源的可靠性和时间确认优先级，如：时间更新的信息优先、来源更可靠的信息优先、用户明确表达的信息优先、任务相关的信息优先。
4. 模糊记忆冲突：各条记忆涉及的可能是同一件事的不同范围，记忆本身并不完全矛盾。这种情况不应该删除旧记忆，而应该对多条记忆进行合并。

**常见解决方法**
1. 给记忆加元数据，对于每条记忆，应该保存含有多个参数的结构化信息，便于后续调整和使用；
2. 建立记忆优先级规则，新记忆写入前，先检索同主题旧记忆，判断对记忆的修改策略，如 `覆盖、合并、废弃、待确认` 四个方案，并设计成为规则，指导 Agent 更新记忆；
3. 引入时间衰减机制，根据记忆的时效性给每条记忆添加一个衰减参数，长期偏好衰减较慢，短期任务衰减较快；
4. 在 RAG 或 Memory Retrieval 阶段记忆检索时，进行冲突监测，选择最可信记忆，对于无法判断的冲突，必要时向用户确认。
5. 最终回答时，只使用 active 状态且与当前任务相关的记忆，从而避免过期或矛盾记忆影响 Agent 决策。
