# MCP

**MCP，即 Model Context Protocol，模型上下文协议**，是人工智能领域中的一个开放通信协议标准，旨在解决大模型与外部工具的交互问题。

LLM 本身是只读的，其可以理解与生成文本，但是无法直接执行相关操作，如查询天气等。为了使 LLM 能够具有 Agent 智能体的能力，其必须可以访问外部工具。所以，为了使每个工具都可以以相同的方式与模型进行对接，涉及了 MCP 作为模型与工具之间交互的标准化协议。

## 底层协议

MCP 是一个语义层的协议，其底层消息协议是基于 JSON-RPC 2.0 协议的。
Client 与 Server 之间的消息必须符合 JSON-RPC 2.0 协议，使用 UTF-8 编码。

JSON-RPC 定义了三类消息：
- `Request`：请求，需要响应。
- `Response`：请求结果，通过相同 `id` 关联。
- `Notification`：通知，不需要响应。

对于传输层，MCP 根据 Server 和 Client 之间的关系选择传输层协议。

如果 Server 和 Client 在同一台机器，也就是本地 Server，MCP 会选择使用标准输入输出传输 JSON-RPC；

如果是远程 Server，则使用 Streamable HTTP 流式传输 MCP。主要的是，Streamable HTTP 不一定使用 SSE 进行流式传输。
也就是说 SSE 只是可选而不是必须。

## 核心组成

MCP 从整体上可以拆分为三类核心角色，分别是 Model 模型，Client 客户端，Server 工具服务端。

Model，即模型。通常是 LLM，负责理解用户意图、决定是否调用相关工具、生成符合 MCP 协议规范的请求文本。模型本身不执行任何操作，只负责理解用户请求、进行决策、组织请求工具。

Client，即客户端。主要位于模型与工具之间。主要负责将模型输出解析成为 MCP 请求，并附近进行权限校验，调用合适的工具对模型请求进行处理，并将工具结果回传给模型使用。在实际工程中，LangChain、LlamaIndex 等都可以视为 MCP Client 的一种实现。

Server，工具提供方。是实际执行功能的系统，如文件系统、数据库、搜索引擎、本地程序等。工具通过 MCP Sever，可以声明能力，接收请求，并返回结构化的结果。

## 设计原则

- **声明式**：工具通过 MCP 声明自身能力和要求等信息，而不是让模型猜测该工具如何使用。
- **上下文感知**：模型可以在请求中附带所需的上下文信息，工具依据提供的上下文信息决定是否执行。
- **结构化通信**：所有交互过程全部基于标准格式(通常是 JSON)，避免模糊的自然语言指令。
- **安全优先**：支持权限控制、沙箱执行、审计日志等机制，防止越权或滥用。
- **语言与平台无关**：MCP 可以运行在任何编程语言或框架上，支持本地或远程工具。
