
# Kafka 中有哪些副本同步机制？

Kafka 的副本同步，本质上就是一个 Leader-Follower 的复制模型。

在 Kafka 中，每一个 Partition 都有一个 Leader 和若干个 Follower，Producer 向 Partition 中写入数据时，只会向 Leader 中写入数据，Follower 则会不断的向 Leader 发起 Fetch 请求，主动从 Leader 中拉取日志，从而完成副本同步。

为了配合 Leader-Follower 复制模型，Kafka 使用 [[02 Kafka 分布式#ISR|ISR 机制]]，即 `In-Sync Replicas`。通过保存一个集合，确保 Follower 中的数据是否在规定时间内持续同步 Leader，如果超过阈值后 Follower 仍未追上 Leader，就会被移出 ISR。

对于每一个 Replica，都会存在一个 LEO，即 Log End Offset，表示某个副本当前日志的末尾位置。每个副本都存在自己的 LEO，通过 LEO，就可以判断当前 Follower 复制到哪里了。

同时，每一个 Partition，都会存在一个 HW，即 High Watermark，标记 ISR 中所有副本都已经安全复制到的位置，消费者一般只能读取到 HW 之前的元素。HW 代表了当前 ISR 整体确认到什么位置了。

Kafka 还会使用 **asks 机制**，控制生产者会等待多少副本才会认定消息发送成功，分别是 **0、1、all**，分别表示：发出去就不管了、Leader 写入成功就不管了、只有满足 ISR 同步条件后才成功。0、1、all，三个参数可靠性逐渐提高。
