# HTTP协议

### 输入URL到展示页面流程
1. 在浏览器中输入指定网页URL
2. 浏览器先查询本地缓存, 如果有则直接返回, 状态码为200或304.
3. 浏览器使用DNS协议, 获取域名对应的IP地址.
4. 浏览器根据IP地址和端口号, 向目标服务器发送TCP连接请求.
5. 浏览器在建立好的TCP上, 向服务器发送HTTP请求报文, 获取网页内容. 在这个过程中, cookies 也会随请求发送给服务器.
6. 服务器收到HTTP请求报文后, 处理请求, 组织HTTP响应报文返回给浏览器
7. 浏览器收到HTTP响应后, 解析响应体中的HTML代码, 渲染网页的结构和样式, 同时根据HTML中其他资源的URL, 继续发起HTTP请求解析资源.
8. 浏览器不需要与服务器通信时, 可以主动关闭TCP或等待服务器关闭.

### HTTP与HTTPS
- **端口**: HTTP 为80, 而 HTTPS 为443.
- **URL前缀**: `http://` 和 `https://`
- **安全性**: HTTP 协议是基于 TCP 的, 所有传输内容都是明文进行, 客户端和服务端之间无法验证对方的身份; HTTPS 协议是运行在 SSL/TLS 之上的 HTTP 协议, 同时 SSL/TLS 运行在 TCP 之上, 所有传输内容都经过加密. 加密采用对称加密, 但对对称加密的密钥使用对方服务器的证书进行了非对称加密. HTTP 安全性较 HTTPS 较差, 但 HTTP 效率相对更高.
- **SEO**: 搜索引擎通常更青睐使用 HTTPS 协议的网站, 因为 HTTPS 能够提供更高的安全性和用户隐私保护.

### HTTP/1.0与HTTP/1.1
- **连接方式**: `HTTP/1.0` 只支持短连接, `HTTP/1.1` 支持长连接.
- **状态响应码**: `HTTP/1.1` 中新添加了大量状态码.
- **缓存机制**: `HTTP/1.0` 中主要使用 `Header` 中的 `If-Modified-Since`, `Expires` 作为缓存的判断标准, 而 `HTTP/1.1` 引入了更多缓存策略, 如 `Entity tag`, `If-Unmodified-Since`, `If-Match`, `If-None-Match` 等.
- **带宽**: `HTTP/1.0` 中存在浪费带宽现象, 当客户端只需要部分对象时, 服务器只能传输全部对象, 且 `HTTP/1.0` 不支持断点续传功能; `HTTP/1.1` 在请求头中加入 range 头域, 允许只请求资源的某个部分, 方便开发者充分利用带宽和连接
- **Host 头**: `HTTP/1.1` 引入了 Host 头段, 用于标记域名, 允许同一个 IP 地址上托管多个域名, 支持虚拟主机的功能, 而 `HTTP/1.0` 没有 host, 不支持虚拟主机.

### HTTP/1.1与HTTP/2.0
- 多路复用: `HTTP/2.0` 在同一连接上可以同时传输多个请求和响应, 互不干扰; 而 `HTTP/1.1` 只能使用串行方式, 对每一对请求和响应都需要独立连接, 而浏览器为控制资源对 `TCP` 连接数量有限制. 这使得 `HTTP/2.0` 在处理多个请求时更加高效, 减少了网络延迟.
- 二进制帧: `HTTP/2.0` 使用二进制帧进行数据传输, 对数据传输更加紧凑高效; 而 `HTTP/1.1` 使用文本格式的报文, 需要传输的数据量更大.
- 队头阻塞: `HTTP/2.0` 引入多路复用技术, 运行多个请求和响应在单个 `TCP` 连接上并行交错传输, 在应用层解决了 `HTTP/1.1` 的队头阻塞问题, 但仍受到 `TCP` 层队头阻塞的影响.
- 头部压缩: `HTTP/1.1` 支持 `body` 压缩不支持 `header` 压缩; `HTTP/2.0` 中, 支持 `Header` 压缩, 使用了专门为 `Header` 压缩设计的 `HPACK` 算法, 减少了网络开销.
- 服务器推送: `HTTP/2.0` 支持服务器推送, 可以在客户端请求资源时, 将其他相关资源一并推送给客户端, 减少了客户端的请求次数和延迟. 而 `HTTP/1.1` 中需要客户端自己发送相关请求.
