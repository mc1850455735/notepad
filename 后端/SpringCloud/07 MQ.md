
# 概述

### 同步调用

**优点**
- 时效性强, 等待到结果后才会返回
**缺点**
- 拓展性差
- 性能下降
- 级联失败问题

### 异步调用

- 异步调用通常是基于消息通知的方式
- 服务不再同步调用业务关联度低的业务, 而是发送消息通知到Broker
- **消息发送者**: 投递消息的人, 就是原来的服务调用者
- **消息接收者**: 接收和处理消息的人, 就是原来的服务提供者
- **消息代理**: 管理, 暂存, 转发消息

**优点**
- 解除耦合, 拓展性强
- 无需等待, 性能好
- 故障隔离
- 缓存消息, 流量削峰填谷
**缺点**
- 不能立即得到调用结果, 时效性差
- 不确定下游业务是否执行成功
- 业务安全依赖于Broker转发器的可靠性

### MQ技术选型
- `Message Queue` 消息队列, 就是存放消息的队列, 也就是异步调用中的 `Broker`

# MQ基础

### 概述

**安装**
- 基于Docker安装 `RabbitMQ`
```shell
docker run \
-e RABBITMQ_DEFAULT_USER=itheima \
-e RABBITMQ_DEFAULT_PASS=123321 \
-v mq-plugins:/plugins \
--name mq \
--hostname mq \
-p 15672:15672 \
-p 5672:5672 \
--network hm-net \
-d \
rabbitmq:3.8-management
```
- 在浏览器中访问 `15692` 端口即可访问 `RabbitMQ` 控制台
- `Connections`: 展示所有消息发送者和消息接收者的状态
- `Channels`: 展示传输消息的通道相关的信息
- `Exchanges`: 交换机
- `Queues`: 队列

**介绍**
- `vitual-host`: 虚拟主机, 起到数据隔离的作用
- `publisher`: 消息发送者
- `consumer`: 消息消费者
- `queue`: 队列, 存储消息
- `exchange`: 交换机, 负责路由消息
![[后端/SpringCloud/Inbox/Pasted image 20251002165455.png]]

**快速入门**
- 在控制台中, 可以直接添加队列, 只必须指定队列名称即可, 其他可省略
- 在控制台中, 可以直接向交换机中发送消息, 从而模拟生产者
- 交换机必须**绑定队列**, 才可以将消息发送到队列中, 如果一个交换机不绑定任何队列, 则发送到交换机中的消息会丢失, 也就是交换机**不存在存储消息能力**
- 在控制台中, 可以直接指定交换机和队列之间的绑定关系

### 数据隔离
- 由于消息队列可以处理的消息量很大, 所以一个项目通常只使用一个消息队列, 对于不同的微服务, 通常使用不同的虚拟主机进行数据隔离

**虚拟主机管理**
- 在控制台中, Admin选项卡下右侧可以进行各种管理
	- Users: 用户管理
	- Virtual Hosts: 虚拟主机管理
- 每个微服务使用不同的用户, 每个用户管理对应的虚拟主机
- 首先添加用户, 指定用户名和密码, 并且可以在Tag中设置用户的角色
	- Administrator: 管理员, 拥有最高权限
- 然后, 切换到对应用户, 并为该用户创建自己的虚拟主机

# Java客户端

### 基础

**概念**
- AMQP (Advanced Message Queuing Protocol): 用于在应用程序之间传递业务消息的开放标准. 该协议与语言和平台无关, 更符合微服务中独立性的要求
- Spring AMQP: 是基于AMQP协议定义的一套API规范, 提供了模板用来发送和接收消息. 包含两部分, 其中spring-amqp是基础抽象, spring-rabbit是底层的默认实现

**快速入门**
- 利用控制台创建队列simple.queue
- 引入spring-amqp依赖
```xml
<!--AMQP依赖，包含RabbitMQ-->  
<dependency>  
    <groupId>org.springframework.boot</groupId>  
    <artifactId>spring-boot-starter-amqp</artifactId>  
</dependency>
```
- 在每个微服务中引入MQ服务端消息, 使微服务连接到MQ
```yaml
spring:
  rabbitmq:
    host: 192.168.199.200
    port: 5672
    virtual-host: /hmall
    username: hmall
    password: 123
```
- 在publisher中直接利用SpringAMQP向队列发送消息
```java
@Test  
public void testSimpleQueue() {  
    String queueName = "simple.queue";  
    String message = "hello springamqp";  
    rabbitTemplate.convertAndSend(queueName, message);  
}
```
- 在consumer中使用SpringAMQP编写消费者, 监听队列消息
- SpringAMQP提供声明式的消息监听, 只需要通过注解在方法上声明要监听的队列名称, SpringAMQP就会把消息传递给当前方法
```java
@Component  
public class SpringRabbitListener {  
    @RabbitListener(queues = "simple.queue")  
    public void listenSimpleQueue(String message) {  
        log.info("监听到simple.queue的消息: " + message);  
    }  
}
```

### WorkQueues
- `Work Queues`, 任务模型, 简单来说就是让多个消费者绑定到同一个队列, 共同消费队列中的消息
- 向同一个队列中发送消息时, 同一个消息只能被一个消费者处理
- 在有多个消费者的情况下, 消息消费的速度会大大提升, 缓解消息堆积
- 默认情况下, `RabbitMQ` 在有多条消息的情况下, 消息的分配是轮询的, 即使消费者处理消息速度不一致
- 依次轮询的方法不考虑消费者是否已经处理完消息, 可能出现消息堆积的情况, 因此需要修改 `application.yml` , 配置 `preFetch` 为1, 确保在同一时刻最多投递给消费者1条消息, 只有处理完才能获取下一条消息
```yaml
spring:  
  rabbitmq:  
    listener:  
      simple:
        prefetch: 1
```

### 交换机
- 交换机的作用主要是**接收**发送者发送的消息, 并将消息**路由**到与其绑定的队列, 常见交换机类型有以下三种
- Fanout: 广播
- Direct: 定向
- Topic: 话题

##### Fanout
- Fanout Exchange会将接收到的消息路由到每一个与其绑定的queue, 所以又叫做 **广播模式**

**代码示例**
- 向交换机中传消息
```java
@Test  
public void testFanoutQueue() {  
    String exchangeName = "hmall.fanout";  
    String message = "hello everyone";  
    rabbitTemplate.convertAndSend(exchangeName, null, message);  
}
```

##### Direct
- Direct Exchange会将接收到的消息根据规则路由到指定的Queue, 因此被称为 **定向路由**
- 每一个Queue都会与Exchange设置一个Binding Key
- 发布者发送消息时, 指定消息的Routing Key
- Exchange将消息路由到Binding Key与消息Routing Key一致的队列

**代码示例**
- 使用 routing key 发送消息
```java
@Test  
public void testDirectQueue() {  
    String exchangeName = "hmall.direct";  
    String message = "hello everyone blue";  
    rabbitTemplate.convertAndSend(exchangeName, "blue", message);  
}
```

##### Topic
- `Topic Exchange` 也是基于 `Routing Key` 做消息路由, 但是其 `routing key` 通常是多个单词的组合, 并通过 `.` 进行分割
- Queue 与 Exchange 指定 Binding Key 时可以使用通配符
	- `#` 代指0个或多个单词 (通常使用)
	- `*` 代指一个单词
- 相比较于 Direct 类型交换机, Topic 允许使用通配符, 拓展性相对较强
- Topic 使用模式匹配相比较直接匹配性能会有影响, 但是通常可以忽略不记

**代码**
- 发送代码示例, 路由时会根据路由规则对 Routing Key 进行匹配
```java
@Test  
public void testTopicQueue() {  
    String exchangeName = "hmall.topic";  
    String message = "hello everyone china news";  
    rabbitTemplate.convertAndSend(exchangeName, "china.news", message);
```


### 基于Bean声明
- 在实际开发过程中, 通过控制台手工添加队列和交换机等显然是不可靠且容易出错的, 所以需要通过定义bean等方法, 通过代码指定队列和交换机
- `SpringAMQP` 提供了几个类, 用来声明队列, 交换机及其绑定关系
	- `Queue`: 用来声明**队列**, 可以使用工厂类 `QueueBuilder` 构建
	- `Exchange`: 用于声明**交换机**, 可以使用工厂类ExchangeBuilder构建
	- `Exchange` 是一个接口, 旗下存在多种不同的实现类, 用以声明各种不同类型的交换机
	- `Binding`: 用于声明队列和交换机的**绑定关系**, 可以用工厂类 `BindingBuilder` 创建

**代码示例**
- 通常在消费者端进行Bean声明等
- Fanout交换机
```java
@Configuration  
public class FanoutConfiguration {  
    @Bean  
    public FanoutExchange fanoutExchange() {  
        // return new FanoutExchange("hmall.fanout");  
        return ExchangeBuilder.fanoutExchange("hmall.fanout").build();  
    }  
    @Bean  
    public Queue fanoutQueue1() {  
        // return new Queue("fanout.queue1");  
        // durable: 持久化, 设置后队列将会持久化到磁盘  
        return QueueBuilder.durable("fanout.queue1").build();  
    }  
    @Bean  
    public Binding fanoutQueue1Binding(Queue fanoutQueue1, FanoutExchange fanoutExchange) {  
        // 如果使用的其他类型交换机, 还需要使用with方法指定bindingKey  
        return BindingBuilder.bind(fanoutQueue1).to(fanoutExchange);  
    }  
}
```
- Direct交换机
```java
@Configuration  
public class DirectConfiguration {  
    @Bean  
    public DirectExchange directExchange() {  
        return ExchangeBuilder.directExchange("hmall.direct").build();  
    }  
    @Bean  
    public Queue directQueue1() {  
        return QueueBuilder.durable("direct.queue1").build();  
    }  
    @Bean  
    public Binding directQueue1BindingRed(Queue directQueue1, DirectExchange exchange) {  
        return BindingBuilder.bind(directQueue1).to(exchange).with("red");  
    }  
    @Bean  
    public Binding directQueue1BindingBlue(Queue directQueue1, DirectExchange exchange) {  
        return BindingBuilder.bind(directQueue1).to(exchange).with("blue");  
    }
}
```

### 基于注解声明
- 由于使用Bean声明的方式在队列信息较复杂的情况下声明语句及其繁琐, 所以引入了基于注解的声明队列和交换机的方式 `@RabbitListener`
- 通过 `bindings` 属性声明要绑定的交换机和队列, 并在其中使用 `@QueueBinding` 注解进行设置; 其中 `value` 为队列名称, `exchange` 为交换器名称, `key` 为 `routing key` 属性设置
```java
@RabbitListener(bindings = @QueueBinding(  
        value = @Queue(name = "direct.queue1"),  
        exchange = @Exchange(name = "hmall.direct", type = ExchangeTypes.DIRECT),  
        key = {"red", "blue"}  
))  
public void listenDirectQueue1(String message) {  
    log.info("监听到 direct.queue1 的消息[{}]", message);  
}
```

### 消息转换器
- 实际传输时是通过字节的方式进行输送, 所以在发送前需要将Object类型对象转换为字节流
- 序列化后的消息类型为 `application/x-java-serialized-object`
- `SpringAMQP` 做消息转换时使用的就是 JDK 自带的 Serialize 方法
- JDK 默认序列化存在以下问题
	- JDK 序列化有安全风险
	- JDK 序列化的消息体积太大
	- JDK 序列化的消息可读性太差
- 建议采用 JSON 序列化替代默认的 JDK 序列化

**步骤**
- 引入 Jackson 依赖
```xml
<!-- jackson依赖 -->  
<dependency>  
    <groupId>com.fasterxml.jackson.core</groupId>  
    <artifactId>jackson-databind</artifactId>  
</dependency>
```
- 在 publisher 和 consumer 中都配置 MessageConvert Bean
```java
@Bean  
public MessageConverter messageConverter() {  
    return new Jackson2JsonMessageConverter();  
}
```
- 监听时, 对应的消息类型要与发送者的消息类型一致
```java
@RabbitListener(queues = "object.queue")  
public void listenObjectQueue2(Map<String, Object> message) {  
    log.info("监听到 object.queue 的消息[{}]", message);  
}
```


# 项目改造

- 在通用包中, 对消息转换器进行配置
```java
@Configuration  
public class MqConfig {  
    @Bean  
    public MessageConverter messageConverter() {  
        return new Jackson2JsonMessageConverter();  
    }
```
- 在消息接收者建立 Listener
```java
@Component  
@RequiredArgsConstructor  
public class PayStatusListener {  
    private final IOrderService orderService;  
    @RabbitListener(bindings = @QueueBinding(  
        value = @Queue(value = "trade.pay.success.queue", durable = "true"),  
        exchange = @Exchange(name = "pay.direct"),  
        key = "pay.success"  
    ))  
    public void listenSuccess(Long orderId) {  
        orderService.markOrderPaySuccess(orderId);  
    }  
}
```
- 在消息发送者处发送消息
- 使用 try-catch 包裹异步调用, 以免影响原有业务
```java
try {  
    rabbitTemplate.convertAndSend("pay.direct", "pay.success", po.getBizOrderNo());  
} catch (AmqpException e) {  
    log.error("异步调用中: " + e);  
}
```
