
# 概述

- 就是网络的关口, 负责请求的路由, 转发, 身份校验等
- 前端直接请求网关, 由网关进行服务地址的判断与转发
- 网关本身也是一个微服务, 转发的依据就是从注册中心中拉取的服务注册表
- 所以网关已经成为了微服务开发必不可少的组件
- 目前有两个常用的网关组件
- Spring Cloud Gateway
	- Spring官方出品
	- 基于WebFlux响应式编程
	- 无需调优即可获得优异性能
- Netfilx Zuul
	- NetFlix出品
	- 基于Servlet的阻塞式编程
	- 需要调优才能达到类似SpringCloudGateway类似的性能

### 入门

- 创建新模块
- 引入网关依赖
```xml
<!-- 网关依赖 -->  
<dependency>  
    <groupId>org.springframework.cloud</groupId>  
    <artifactId>spring-cloud-starter-gateway</artifactId>

<!-- nacos -->  
<dependency>  
    <groupId>com.alibaba.cloud</groupId>  
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>  
</dependency>  
<!-- 负载均衡依赖 -->  
<dependency>  
    <groupId>org.springframework.cloud</groupId>  
    <artifactId>spring-cloud-starter-loadbalancer</artifactId>  
</dependency>
```
- 编写启动类
- 配置路由规则
	- id: 路由唯一标识
	- uri: 路由目标微服务, lb代表负载均衡
	- predicates: 路由断言, 判断请求路径是否符合规则, 符合则路由到目标
	- 断言中, 等号左侧代表匹配模式, 右侧代表具体规则, 这是一种简写
	- 换行代表and关系, 逗号代表or关系
```yaml
server:  
  port: 8080  
spring:  
  application:  
    name: gateway  
  cloud:  
    nacos:  
      server-addr: 192.168.199.200:8848  
    gateway:  
      routes:  
        - id: item-service  
          uri: lb://item-service  
          predicates:  
            - Path=/items/**,/search/**  
        - id: user-service  
          uri: lb://user-service  
          predicates:  
            - Path=/user/**,/addresses/**
```

# 网关登录校验

- 由于JWT校验操作在绝大多数微服务中都需要进行, 所以将其抽取到网关中进行操作, 网关校验完成后才会放行请求
- 路由映射完成后, 会将请求放入请求处理器中, 请求处理器会加载网关中配置的多个过滤器, 放入集合中并排序, 形成过滤器链
- 过滤器内部可以包含两部分逻辑: 分别是pre和post, 分别会在请求路由到微服务之前和之后执行
- Netty路由过滤器: 负责将请求转发到微服务, 当微服务返回结果后存入上下文
- 网关过滤器通过JWT校验后, 会将得到的用户信息保存到Http请求的请求头当中

### 自定义过滤器

**概念**
- 网关过滤器分为两种, 两种过滤器的过滤方法签名完全相同
	- `ServerWebExchange`: 请求上下文信息, 包含整个过滤器链内共享数据
	- `GatewayFilterChain`: 过滤器链. 当前过滤器执行完后, 要调用过滤器链中的下一个过滤器
	- `Mono<Void>`: 定义的Post回调函数, 微服务返回后执行回调函数中内容
- `GatewayFilter`: 路由过滤器, 作用于任意指定的路由, 默认不生效, 要配置到路由后生效
- `GlobalFilter`: 全局过滤器, 作用范围是所有路由; 声明后自动生效
- `Ordered`: 实现过滤器排序

**自定义GlobalFilter**
```java
@Component  
public class MyGlobalFilter implements GlobalFilter, Ordered {  
    @Override  
    public Mono<Void> filter(ServerWebExchange exchange, 
                             GatewayFilterChain chain) {  
        // TODO: 模拟登录校验逻辑  
        ServerHttpRequest request = exchange.getRequest();  
        HttpHeaders headers = request.getHeaders();  
        System.out.println("headers = " + headers);  
        return chain.filter(exchange);  
    }  
  
    @Override  
    public int getOrder() {  
        return 0;  
    }  
}
```

**自定义无参GatewayFilter**
- 实现自定义GatewayFilter ,需要实现一个`AbstractGatewayFilterFactory`
- 与全局过滤器不同, 路由过滤器需要基于配置实现对过滤器的设置, 且不同路由的相同过滤器配置可能不同, 所以通过工厂模式, 使用工厂来基于配置创建过滤器对象
- 约定要求, 所有路由过滤器工厂类都必须以`GatewayFilterFactory`为后缀, 类名的前缀在配置中作为过滤器的名称
- 在工厂内返回值中, 如果直接使用GatewayFilter接口的匿名实现类, 则会面临因匿名类无法实现两个接口而不能使用Ordered接口实现优先级的困难
- 对此, 使用一个已经实现好的类 `OrderedGatewayFilter` 同时实现Ordered接口和GatewayFilter接口, 传入一个实现了GatewayFilter接口的匿名类即可
- 示例如下
- 声明一个自定义GatewayFilter
```java
@Component  
public class PrintAnyGatewayFilterFactory extends AbstractGatewayFilterFactory<Object> {  
    @Override  
    public GatewayFilter apply(Object config) {  
        return new OrderedGatewayFilter(new GatewayFilter() {  
            @Override  
            public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {  
                System.out.println("print any filter running");  
                return chain.filter(exchange);  
            }  
        }, 1);  
    }  
}
```
- 在配置类中进行使用
```yaml
spring:  
  cloud:  
    gateway:  
      default-filters:  
        - PrintAny
```

**自定义有参GatewayFilter**
- 自定义配置属性类, 成员变量名称需要与映射函数中的相同
- 定义函数`shortcutFieldOrder`, 定义参数顺序与变量之间的映射关系
- 在构造函数中, 将自定义配置类的字节码传递给父类构造函数, 父类负责读取yaml配置并对配置类对象赋值
- 修改父类`AbstractGatewayFilterFactory`的泛型参数为自定义配置类的类型, 同时apply方法的参数类型也需要修改成对应的Config配置类
```java
@Component  
public class PrintAnyGatewayFilterFactory extends AbstractGatewayFilterFactory<PrintAnyGatewayFilterFactory.Config> {  
    @Override  
    public GatewayFilter apply(Config config) {  
        return new OrderedGatewayFilter(new GatewayFilter() {  
            @Override  
            public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {  
                System.out.println("print any filter running");  
                return chain.filter(exchange);  
            }  
        }, 1);  
    }  
  
    @Data  
    public static class Config {  
        private String a;  
        private String b;  
        private String c;  
    }  
  
    @Override  
    public List<String> shortcutFieldOrder() {  
        return List.of("a", "b", "c");  
    }  
  
    public PrintAnyGatewayFilterFactory() {  
        super(Config.class);  
    }  
}
```

### 实现登录校验

- 在网关中基于过滤器实现登录校验功能
- 利用 `antPathMatcher` 做通配符路径校验, `antPathMatch`不是spring中定义的bean, 需要使用时手动`new`
```java
@Override  
public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {  
    // 获取用户信息request  
    ServerHttpRequest request = exchange.getRequest();  
    // 判断是否需要做登录拦截  
    if(isExclude(request.getPath().toString())) {  
        // 直接放行  
        return chain.filter(exchange);  
    }  
    // 从请求头获取token  
    String token = null;  
    List<String> headers = request.getHeaders().get("authorization");  
    if(headers != null && !headers.isEmpty()) {  
        token = headers.get(0);  
    }  
    // 校验并解析token  
    Long userId = null;  
    try {  
        userId = jwtTool.parseToken(token);  
    } catch (Exception e) {  
        // 用户未授权, 拦截, 设置响应状态码  
        ServerHttpResponse response = exchange.getResponse();  
        response.setStatusCode(HttpStatus.UNAUTHORIZED);  
        // 标示响应终止, 直接返回  
        return response.setComplete();  
    }  
    // 获得用户信息, 将其保存到请求头, 传递用户信息  
    System.out.println("userId = " + userId);  
    // 放行  
    return chain.filter(exchange);  
}  
  
private boolean isExclude(String path) {  
    List<String> excludePaths = authProperties.getExcludePaths();  
    for (String pathPattern : excludePaths) {  
        if (antPathMatcher.match(pathPattern, path)) {  
            return true;  
        }  
    }  
    return false;  
}
```

### 传递用户信息

- 网关通过过滤器获取JWT中的token信息, 将其作为http的请求头加入到对微服务的请求当中
	- 要修改转发到微服务的请求, 需要用到ServerWebExchange类提供的api
```java
@Override  
public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {  
    ...
    // 获得用户信息, 将其保存到请求头, 传递用户信息  
    String userInfo = userId.toString();  
    ServerWebExchange newExchange = exchange.mutate().request(builder -> {  
        builder.header("user-info", userInfo);  
    }).build();  
    // 放行  
    return chain.filter(newExchange);  
}
```
- 微服务获取到对应的请求后, 通过拦截器根据token获取到对应的用户id, 并将用户信息保存到ThreadLocal当中
- 由于每一个微服务模块都需要拦截器, 所以直接在common中定义对应的拦截器, 在每个模块中都进行复用
```java
public class UserInfoInterceptor implements HandlerInterceptor {  
    // 该拦截器只负责将网关发送来的请求头保存到ThreadLocal中  
    // 不需要判断是否应该放行, 因为在网关中已经进行了检查  
    @Override  
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {  
        // 获取登录用户信息  
        String userInfo = request.getHeader("user-info");  
        // 判断是否获取了用户, 如果有, 存入ThreadLocal  
        if(StrUtil.isNotBlank(userInfo)) {  
            UserContext.setUser(Long.valueOf(userInfo));  
        }  
        // 放行  
        return true;  
    }  
  
    @Override  
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response, Object handler, Exception ex) throws Exception {  
        UserContext.removeUser();  
    }  
}
```
- 由于网关不需要SpringMvc相关的功能, 所以不需要引入该拦截器, 使用`@ConditionalOnClass` 注解标注对应配置类, 使其在网关内不生效
```java
@Configuration  
@ConditionalOnClass(DispatcherServlet.class)  
public class MvcConfig implements WebMvcConfigurer {  
    @Override  
    public void addInterceptors(InterceptorRegistry registry) {  
        // 默认拦截所有路径  
        registry.addInterceptor(new UserInfoInterceptor());  
    }  
}
```
- 配置SpringBoot扫描配置类文件路径, 使所有项目可以直接扫描到不同包路径下的配置类, 而不需要进行导入
- `spring.factories` : 
```
org.springframework.boot.autoconfigure.EnableAutoConfiguration=\  
  com.hmall.common.config.MyBatisConfig,\  
  com.hmall.common.config.MvcConfig,\  
  com.hmall.common.config.JsonConfig
```

### OpenFeigh传递用户
- OpenFeigh中提供了一个拦截器接口, 所有由OpenFeign发起的请求都会先调用拦截器处理请求
- 其中的RequestTemplate类中提供了一些方法可以让我们修改请求头, 当请求发出时, 会先进入拦截器, 经拦截器处理后, 再发往其他微服务
```java
@Bean  
public RequestInterceptor userInfoRequestInterceptor() {  
    return new RequestInterceptor() {  
        @Override  
        public void apply(RequestTemplate template) {  
            Long userId = UserContext.getUser();  
            if (userId != null) {  
                template.header("user-info", userId.toString());  
            }  
        }  
    };  
}
```
- 定义完成拦截器后, 在对应的SpringBoot启动类中添加扫描路径
```java
@MapperScan("com.hmall.trade.mapper")  
@SpringBootApplication  
@EnableFeignClients(  
        value = "com.hmall.api.client",  
        defaultConfiguration = DefaultFeignConfig.class  
)  
public class TradeApplication {  
    public static void main(String[] args) {  
        SpringApplication.run(TradeApplication.class, args);  
    }  
}
```


# 配置管理

**问题**
- 微服务重复配置过多, 维护成本高
- 业务配置经常变动, 每次修改都要重启服务
- 网关路由配置写死, 如果变更需要重启网关

**配置管理核心功能**
- 所有微服务的配置共享, 减少了管理成本
- 配置变更后及时推送, 避免配置更新后重启, 实现热更新
- nacos既可以实现注册中心功能, 还可以实现配置管理功能

### 配置共享

**步骤**
- 将需要的共享配置添加到nacos当中
	- 对于有差异的部分, 使用事先声明好的配置文件变量替换
	- 示例: `${hm.db.host}` - 普通变量, `${hm.db.port:3306}` - 默认值3306
- 基于NacosConfig拉取共享配置代替微服务的本地配置
	- 首先先尝试拉取Nacos配置, 基于Nacos配置完成SpringCloud上下文初始化, 使用bootstrap.yml初始化nacos服务器地址等关键配置信息
	- SpringCloud上下文加载完毕后, 加载SpringBoot的上下文
- 引入依赖
```xml
<!-- nacos配置依赖 -->  
<dependency>  
    <groupId>com.alibaba.cloud</groupId>  
    <artifactId>spring-cloud-starter-alibaba-nacos-config</artifactId>  
</dependency>  
<!-- 读取bootstrap文件 -->  
<dependency>  
    <groupId>org.springframework.cloud</groupId>  
    <artifactId>spring-cloud-starter-bootstrap</artifactId>  
</dependency>
```
- 新建配置文件
```yaml
spring:  
  application:  
    name: cart-service  
  profiles:  
    active: dev  
  cloud:  
    nacos:  
      server-addr: 192.168.199.200:8848  
      config:  
        file-extension: yaml  
        shared-configs:  
          - data-id: shared-jdbc.yaml  
          - data-id: shared-log.yaml  
          - data-id: shared-swagger.yaml
```

### 配置热更新

**概念**
- 当修改配置文件中的配置时, 微服务无需重启即可使配置生效
- 前提条件: 
- 1. nacos中要有一个与微服务名有关的配置文件
- `[spring.application.name-[spring.active.profile].[file-extension]]`
	- `spring.application.name` : 微服务名称
	- `spring.active.profile` : 项目profile(可选), 不加则所有环境生效
	- `file-extension` : 文件后缀名
- 2. 微服务中要以**特定方式**读取需要热更新的配置属性
	- 使用 `@ConfigurationProperties(prefix = "配置路径")` 进行读取, 类中属性直接与配置文件中的属性按名称进行对应 (推荐)
	- 使用 `@Value("${配置路径.属性名}")` 方式进行注入, 并在类上标记 `@RefreshScope` 来说明当前类中属性需要热更新
```java
@Data  
@Component  
@ConfigurationProperties(prefix = "hm.cart")  
public class CartProperties {  
    private Integer maxItems;  
}
```

### 动态路由

**概述**
- 实现动态路由首先要把路由配置保存在nacos中, 当nacos中的路由配置变更时, 推动最新配置到网关, 实时更新网关中的路由信息
- 要实现动态路由配置, nacos只负责推送配置信息, 对于配置的更新要由用户完成, 需要在网关中完成: 监听nacos配置变更的消息; 配置变更时, 将最新的路由信息更新到网关路由表中
- 文档: https://nacos.io/docs/latest/manual/user/java-sdk/usage

**监听Nacos配置变更**
- 如果想要对配置的更改进行监听, 可以使用 `addListener` 进行配置
- `public void addListener(String dataId, String group, Listener listener)`
	- `Listener`: 监听器，配置变更进入监听器的**回调函数**
- 为了同时实现初始化配置和添加监听器, 可以通过如下函数进行实现
- `String getConfigAndSignListener(String dataId, String group, long timeoutMs, Listener listener)`
```java
@PostConstruct  
public void initRouteConfigListener() throws NacosException {  
    // 项目启动时, 先拉取配置并添加配置监听器  
    String configInfo = nacosConfigManager  
            .getConfigService()  
            .getConfigAndSignListener(dataId, group, 5000, new Listener() {  
                @Override  
                public Executor getExecutor() {  
                    return null;  
                }  
  
                @Override  
                public void receiveConfigInfo(String configInfo) {  
                    // 监听到配置变更需要去更新路由表  
                    updateConfigInfo(configInfo);  
                }  
            });  
    // 第一次读取到的配置也需要更新到路由表  
    updateConfigInfo(configInfo);  
}
```

**更新路由表**
- 监听到路由信息后, 可以通过RouteDefinitionWriter来更新路由表
- 为方便解析, 直接使用json格式保存路由信息, 并通过相关工具类进行解析
```json
[
    {
        "id": "trade-service",
        "predicates": [{
            "name": "Path",
            "args": {
                "_genkey_0": "/orders/**"
            }
        }],
        "filters": [],
        "uri": "lb://trade-service"
    },
]
```
```java
public void updateConfigInfo(String configInfo) {  
    log.debug("监听到路由配置信息: " + configInfo);  
    // 解析配置, 转为RouteDefinition  
    List<RouteDefinition> routeDefinitionList = 
        JSONUtil.toList(configInfo, RouteDefinition.class);  
    // 删除旧的路由表  
    for (String routeId : routeIds) {  
        routeDefinitionWriter
            .delete(Mono.just(routeId)).subscribe();  
    }  
    // 清空路由表记录  
    routeIds.clear();  
    // 更新路由表  
    for (RouteDefinition routeDefinition : routeDefinitionList) {  
        // 更新路由表  
        routeDefinitionWriter
            .save(Mono.just(routeDefinition)).subscribe();  
        // 记录路由表id, 便于下次更新后删除  
        routeIds.add(routeDefinition.getId());  
    }  
}
```
