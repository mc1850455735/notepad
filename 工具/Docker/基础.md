# 基础安装

- 当利用Docker安装应用时, Docker会自动搜索并下载应用的镜像 (image). 
- 镜像不仅包含应用本身, 也包含应用运行所需要的环境, 配置, 系统函数库. 
	- Docker会在安装镜像时安装镜像使用到的系统的系统函数库, 所以Docker安装的应用可以做到跨系统运行
- Docker会在运行镜像时创建一个隔离环境, 称之为容器 (container).
	- 已经下载过的镜像再安装时, 直接创建时不需要消耗额外时间下载镜像
- **镜像仓库** - 用于存储和管理镜像的平台, Docker官方维护了一个公共仓库[Docker Hub](https://hub.docker.com/)

# 命令解析

- 对命令 `docker run -d --name mysql -p 3306:3306 -e TZ=Asia/Shanghai -e MYSQL_ROOT_PASSWORD=root mysql` 进行解析
	- docker run : 创建并运行一个容器
	- -d : 使容器在后台运行
	- --name mysql : 为容器起名, 必须唯一
	- -p 3306:3306 : 创建端口映射
		- docker容器中的端口对外是不可访问的, 将容器的端口与宿主机的端口创建对应的映射关系, 即可通过宿主机访问容器
		- 前面为宿主机端口, 后面为容器内端口
	- -e KEY=VALUE : 设置环境变量, 具体需要什么变量由制作镜像的作者来决定
	- mysql : 指定运行的镜像的名字
	- 镜像名称一般分为两部分组成: `[repository]:[tag]`
		- 其中repository是镜像名
		- tag是镜像的版本
	- 没有指定tag时, 默认为latest, 代表最新版本的镜像


# 常见命令

Docker最常见的命令为操作镜像以及容器的命令
- docker pull : 从镜像仓库中拉取镜像到本地
- docker images : 查看所有的本地镜像
- docker rmi : 从本地删除镜像
- docker build : 自行定义镜像
- docker save : 将定义好的镜像以压缩包形式保存到本地
- docker load : 使用导出的压缩包将项目加载到docker中
- docker push : 将自己的镜像推送到服务器 (公开服务器或私服)
- docker run : 创建一个docker容器并在其中运行镜像
	- 如果想要启动一个docker容器, 不要重复使用docker run命令, 否则会导致多次创建docker容器
- docker stop : 停止docker容器中的相关进程(但是并不会删除容器)
- docker start : 启动容器中的相关进程
- docker ps : 查看当前docker容器的运行状态
- docker rm : 删除对应的docker容器
	- 不要与用于删除镜像的docker rmi搞混
- docker logs : 查看docker运行日志
- docker exec : 进入docker容器内部执行指令

**案例**
- 查看DockerHub, 拉取Nginx镜像, 创建并运行Nginx容器
- 在DockerHub中搜索Nginx镜像, 查看镜像的名称
	- `nginx`
- 拉取Nginx镜像
	- `docker pull nginx`
- 查看本地镜像列表
	- `docker images`
- 将本地镜像打包成为压缩包
	- `docker save -o nginx.tar nginx:latest`
- 删除本地镜像
	- `docker rmi nginx`
- 加载压缩包中的镜像
	- `docker load -i nginx.tar`
- 创建并运行Nginx容器
	- `docker run -d --name nginx -p 80:80 nginx`
- 查看容器
	- 运行中容器 : `docker ps`
	- 查看所有容器 : `docker ps -a`
	- 简化输出 : `docker ps --format "table {{.ID}}\t{{.Image}}\t{{.Ports}}\t{{.Status}}\t{{.Names}}"`
- 停止容器
	- `docker stop nginx`
- 再次启动容器
	- `docker start nginx`
- 查看容器日志
	- 查看目前容器日志 : `docker logs`
	- 持续输出容器日志内容 : `docker logs -f`
- 进入Nginx容器
	- 使用可交互终端, 通过bash进行交互 : `docker exec -it nginx bash`
	- 也可以直接执行相关指令 : `docker exec -it mysql mysql -uroot -p`
	- 使用exit退出容器
- 删除容器
	- `docker rm nginx`
	- 强制删除 : `docker rm -f nginx`

**命令别名**
- 对于某些命令, 可能由于其简化输出操作过于繁琐, 所以可以通过设置Linux命令别名的方式简化输入
- 在 `~/.bashrc` 中, 加入自己提前准备好的别名
	- `alias dps='docker ps --format "table {{.ID}}\t{{.Image}}\t{{.Ports}}\t{{.Status}}\t{{.Names}}"'`
	- `alias dis='docker images'`
- 使用 `source ~/.bashrc` 加载配置

# 数据卷

**数据卷**
- **数据卷**(volume)是一个虚拟目录, 是**容器内目录**与**宿主机目录**之间映射的桥梁
- 数据卷的信息存储在 `/var/lib/docker/volumes` 内, Docker会实现数据卷与容器的双向绑定, 在_data中的任何修改都会同步到对应的文件中

**相关命令**
- `docker volume create` : 创建数据卷
- `docker volume ls` : 查看所有数据卷
- `docker volume rm` : 删除指定数据卷
- `docker volume inspect` : 查看某个数据卷的详情
- `docker volume prune` : 清除数据卷
- 执行docker run命令时, 使用 `-v 数据卷:容器内目录` 可以完成数据卷挂载, 如果创建时没有挂载数据卷, 则不能重新挂载
- 数据卷名不能与其他卷名冲突
- 创建容器时, 如果挂载了数据卷且数据卷不存在, 会自动创建数据卷

**案例01** => 利用Nginx容器部署静态资源
- 创建Nginx容器, 修改nginx容器内html目录下的index.html文件
	- 根据文档可知, nginx静态资源目录在容器环境中的位置为 `/usr/share/nginx/html`
	- 由于docker容器中只具有程序运行必备的系统程序库, 没有修改相关软件, 且直接修改原始文件相对繁琐, 所以使用**数据卷**进行静态文件的部署
	- 修改数据卷中的内容, 即可做到对容器内静态资源进行修改
- 将静态资源部署到nginx的html目录
	- 直接将相应html静态资源加入到数据卷中的`_data`文件夹即可

**案例02** => 实现MySQL容器的数据挂载
- 查看MySQL容器, 查看是否有数据卷挂载
	- `docker inspect` : 查看容器的详情
	- MySQL容器创建时, 会自动创建一个数据卷, 且为其分配一个独特的名称, 这种自动创建的数据卷被称为匿名卷
	- 匿名卷中保存的信息为MySQL存储的数据
- 基于宿主机目录实现MySQL数据目录, 配置文件, 初始化脚本的挂载
	- 可以不将MySQL数据卷挂载到volume目录, 而是指定一个任意目录进行挂载
	- 执行docker run时, 使用 `-v 本地目录:容器内目录` 可以完成本地目录的挂载, 本地目录必须以`/`或`./`开头, 否则会被识别为数据卷的名称
	- 数据目录 : 挂载到容器内的 `/var/lib/mysql` 目录
	- 配置文件 : 挂载到容器内的 `/docker-entrypoint-initdb.d` 目录
	- 初始化脚本 : 挂载到容器内的`/etc/mysql/conf.d` 目录

**命令示例**
```shell
docker run -d \
--name mysql \
-p 3306:3306 \
-e TZ=Asia/Shanghai \
-e MYSQL_ROOT_PASSWORD=root \
-v /root/mysql/data:/var/lib/mysql \
-v /root/mysql/conf:/docker-entrypoint-initdb.d \
-v /root/mysql/init:/etc/mysql/conf.d \
mysql
```

# 自定义镜像

- 镜像就是包含了应用程序, 程序运行的系统函数库, 运行配置等文件的文件包, 构筑镜像的过程其实就是把上述文件打包的过程

**示例** - 部署一个Java应用步骤
- 准备一个Linux服务器
- 安装JRE并配置环境变量
- 拷贝Jar包
- 运行Jar包

**打包**
- 在打包Docker镜像的时候, 不是作为一个单独的压缩包进行打包的, 而是按功能分成一个个不同的压缩包分别进行压缩或者解压缩
- 各个不同操作所构成的部分, 在Docker中被称为 **层**(Layer) , 添加安装包, 依赖, 配置等, 每一次操作都可以形成新的一层
	- 通过分层操作, 可以实现不同的镜像共享某些基础的层
- 这些最基础的层, 如应用依赖的系统函数库, 环境, 配置, 文件等, 被称为 **基础镜像**(Base Image), 有了基础镜像, 就可以实现不同层的共享
- 最顶部的层, 作为镜像运行的 **入口**(Entrypoint) , 一般是程序启动的脚本和参数

**Dockerfile**
- Dockerfile就是一个文本文件, 其中包含一个个的指令(Instruction) , 用指令来说明要执行说明操作来构建镜像.
- 将来, Docker可以根据Dockerfile帮我们构建镜像
- 常见指令如下
	- `FROM` : 指定基础镜像
	- `ENV` : 设置环境变量, 可在后面指令使用
	- `COPY` : 拷贝本地文件到镜像的指定目录
	- `RUN` : 执行Linux的shell命令, 一般是安装过程的命令
	- `EXPOSE` : 指定容器运行时监听的端口, 给镜像的使用者看
	- `ENTRYPOINT` : 镜像中应用的启动命令, 容器运行时调用

**示例** - 基于Ubuntu构建Java应用
```docker
FROM ubuntu:16.04
ENV JAVA_DIR=/usr/local
COPY ./jdk8.tar.gz $JAVA_DIR/
COPY ./docker-demo.jar /tmp/app.jar
RUN cd $JAVA_DIR \ && tar -xf ./jar8.tar.gz \ && mv ./jdk1.8.0_144 ./java8
ENV JAVA_HOME=$JAVA_DIR/java8
ENV PATH=$PATH:$JAVA_HOME/bin
ENTRYPOINT ["java", "-jar", "/app.jar"]
```

**简化**
- 基础Java的JDK镜像 : `openjdk` , 其中包含所有的jdk镜像
- `openjdk:11.0-jre-buster` : 使用Java11的Ubuntu环境
```docker
FROM openjdk:11.0-jre-buster
COPY docker-demo.jar /app.jar
ENTRYPOINT ["java", "-jar", "/app.jar"]
```

**使用**
- 当编写好Dockerfile后, 可以利用下面的命令来构建镜像
	- `docker build -t myImage:1.0 .`
- `-t` : 给镜像起名, 格式仍为`repository:tag`, 不指定tag时, 默认为latest
- `.` : 指定Dockerfile所在的目录, 如果就在当前目录, 则指定为 `.`
- Dockerfile文件的名字只能是Dockerfile, 不能进行更改

# 网络

- 通过 `docker inspect` 名称查看容器, 可以获得该容器的IP
- docker每个容器的系统都是相互独立的, 之所以可以为其分配连续的IP乃至于通信, 是因为他们都具有相同的网关
- 在本机中安装完成docker后, 就会在本机中创建一张虚拟的网卡, 该网卡默认名称为docker0, 并且会给该网卡创建一个虚拟的网桥, 该网卡的IP地址为 `172.17.0.1/16`
- 默认情况下, 所有容器都是以bridge方式连接到Docker的虚拟网桥Docker0上, 虽然可以通过docker自动分配的IP进行相互通信, 但是自动分配的IP容易发生变化, 不能用于稳定通信

**docker网络操作**
- 加入自定义网络的容器才能够通过**容器名**互相访问, Docker的网络操作命令如下
- `docker network create` : 创建一个网络
- `docker network ls` : 查看所有网络
- `docker network rm` : 删除指定网络
- `docker network prune` : 清除未使用的网络
- `docker network connect` : 使指定容器连接加入某网络
- `docker network disconnect` : 使指定容器连接离开某网络
- `docker network inspect` : 查看网络详细信息
- 在创建容器时, 可以通过 `--network` 指定要使用的网络, 指定后, 新建的容器将不再存在默认的docker0网络, 只包含初始指定的网络
