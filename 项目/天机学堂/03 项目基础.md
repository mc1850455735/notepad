# 环境搭建

## 企业开发环境

企业开发中通常使用微服务进行，在大型微服务项目中，不能将所有项目代码都拉取到本地统一进行测试，通常可能存在以下原因：
- 可能没有其他模块的代码拉取权限。
- 微服务运行环境过于复杂，本地部署成本高。
- 微服务模块较多，本地计算机性能难以支撑。

在开发的不同阶段，有不同的测试手段：
- 单元测试：测试最小可测试单元
- 集成测试：验证某个功能接口
- 组件测试：验证整个微服务组件
- 端对端联调：验证整个系统

Mock 是一种模拟的服务，提前把微服务所需要暴露的接口定义出来，使各个微服务之间可以实现并行开发。在 Mock 中提前设置好接口规则，Mock 将基于接口规则模拟生成出一套完整的服务。

## 持续集成环境

持续集成是一种 DevOps 的软件开发实践，DevOps 分别代表  Development 和 Operations，代表打破开发与运维之间的隔阂。开发和集成之间最大的问题是开发和发布环节的脱离。

持续集成要做的就是：1. 自动构建、发布、测试 2. 防止主干和分支之间存在较大差异 3. 快速发现并解决错误。通过这种方式，可以保证项目整体错误维持在可以控制的水平，做到快速、高水平的开发。

持续集成核心：Jenkins。Jenkins 负责获取代码、编辑代码、构建代码，是整个持续集成的核心。Gogs 是一个轻量化的 Git 私服，负责 Git 的托管、代码的存储等。
