# 认识AI

## 什么是AI

人工智能(AI，Artificial Intelligence)，是让机器模拟人类智能的技术，使其可以像人类一样学习、推理、感知和决策。

AI 之所以智能，是因为他底层是基于 Transformer 架构实现的。Transformer 是 AI 处理语言的核心架构。其核心是“自注意力机制”，使 AI 能够像人一样通过上下文信息理解每个词的含义。

## 大模型原理

大模型的核心能力是通过输入的内容预测下一个词。其核心底层架构是 Transformer，通过自注意力机制，使模型具有能力，像人类一样自动关注输入内容中哪些词更重要。

在模型训练过程中，需要先进行预训练，通过大量文本数据，学习语言规律，建立模型知识库。模型预训练完成后，用户使用过程中可以进行微调，通过使用特定的任务数据调整模型，使其更符合用户预期。

大模型运行的本质是通过概率进行预测。每需要输出一个词时，模型计算所有可能词的概率，并选择概率最高的一个作为模型的输出，也可能会在所有高概率词中进行随机选择，增加模型的多样性。

正是因为大模型依据概率进行回答，所以会存在“幻觉”。所以，对大模型生成的数据，应该进行数据优化，加入人工审核，提醒用户自行验证等。

### 纯Prompt

Prompt，即提示词。很多简单的应用只需要足够好的提示词就可以实现，这种实现应用的模式就被称为纯 Prompt 模式。

由于不同的提示词可以让大模型给出差异巨大的答案。不断雕琢提示词，优化大模型给出的答案，这个过程就叫做 Prompt Engine，提示词工程。

### Function Calling

大模型虽然可以理解自然语言，理解用户意图，但是无法直接操作数据库、执行严格的业务规则。这时就可以通过整合传统的应用增强大模型的能力。

简单来说，可以将传统应用中的功能封装成为一个个函数( Function / Tool)。在提示词中，通过描述用户需求并描述清楚每个函数的作用，使AI理解用户意图，判断什么时候调用哪个函数，并将任务拆解为多个步骤( Agent )。

当 AI 执行到某一步，需要调用某个函数时，返回要调用的函数名、函数需要的参数信息。传统应用接收到数据后，可以调用本地函数，并把函数执行结果封装为提示词，再次发送给 AI。依次类推，最终得到结果。

值得注意的是，并不是所有模型都支持 Function Calling。

### RAG

RAG，全称 Retrieval Augmented Generation，检索增强生成。简单来说就是把信息检索技术和大模型结合的方案。大模型在知识角度存在很多限制，如时效性差，训练数据通常都是旧数据，无法实时更新；缺少专业知识，大模型训练通常采集通用数据，缺乏专业数据。

RAG 就是利用信息检索技术拓展大模型的知识库，以此解决大模型的知识限制。简单来说 RAG 分为两个模块：检索模块，负责存储和检索拓展的知识库，通过拆分文本，并将文本片段转换为向量，根据向量计算文本相似度，同时将相关知识信息向量存储到向量数据库中，将来根据用户提问检索文本片段；生成模块，将检索到的片段与用户提问结合成为新的提示词，形成更丰富的上下文信息，并调用模型根据提示词生成更准确的回答。

**什么是Token**
Token 是模型用来表示自然语言文本的基本单位，也是模型 API 的计费单位。一般情况下，1英文字符≈0.3 token，1中文字符≈0.6 token。同时，大模型输出和输出都分别计算 token，也就是双向收费。

### Fine-tuning

Fine-tuning，即模型微调。就是在预训练大模型的基础上，通过企业自己内部数据对模型做进一步的训练，使大模型的回答更加符合自己企业的业务需求。这个过程通常需要在模型参数上进行细微修改，以达到最佳性能表现。

进行微调时，通常会保留模型的大部分结构和参数，只对其中的一小部分进行调整。这样做可以利用预训练模型已经学习到的知识，同时减少了训练时间和计算资源的损耗。微调过程有以下几个关键步骤：

1. 根据任务需求，选择已经在大量数据上进行过训练的、合适的预训练模型。
2. 收集和准备与任务相关的数据集，将这些数据用于微调模型。
3. 调整学习率、批次大小、训练轮次等超参数，保证模型可以有效学习到新任务的特征。
4. 使用特定任务对模型进行训练，通过前向传播、损失计算、反向传播和权重更新等步骤，不断优化模型性能。

模型微调虽然更加灵活强大，但需要大量计算资源，同时调参过程复杂，存在较高过拟合风险。总之，Fine-tuning 成本较高，难度大，不适合大多数企业。通过前三种技术方案已经可以满足大多数需求。

### 技术选型

开发成本由低到高，四种方案排序如下：Prompt < Function Calling < RAG < Fine-tuning。所以选择技术时，应遵循在达成目标效果的前提下，尽量降低开发成本这一首要原则。

## 阿里云百炼

### 文本调试

temperature 和 top_p 均可控制模型生成文本的多样性，因此建议只设置其中一个值。推荐设置 temperature，因为这是大部分模型的通用参数。

**temperature**
采样温度，控制模型生成文本的多样性。temperature 越高，生成的文本更多样；反之，生成的文本更确定。取值范围为 `[0,2)`

**top_p**
采样的概率阈值，控制模型生成文本的多样性。temperature 越高，生成的文本更多样；反之，生成的文本更确定。取值范围为 `[0,1)`

## Lobe Chat

### 什么是Lobe Chat

Lobe Chat 是一个开源的 AI 聊天机器人框架，运行用户基于大语言模型快速构建和自定义对话应用。核心特点包括：
- 代码开源公开。用户可自行部署到本地或私有服务器，保障数据隐私。
- 多模型支持。兼容 OpenAI 等云端 API，也支持本地部署的模型。
- 可拓展性。提供插件系统，可集成搜索引擎、数据库等工具。
- 交互性好。提供简洁界面，适合开发者快速调试以及普通用户直接使用。

### 部署

可直接在 Linux 上使用 Docker 进行安装，安装版本为 1.70.10。安装完成后，使用 `http://{虚拟机ip}:3210/chat` 地址查看。
`docker run -d -p 3210:3210 --name lobe-chat registry.cn-beijing.aliyuncs.com/itcast/lobe-chat:1.70.10`

## 攻击防范

- 奶奶漏洞
- 提示注入：在用户输⼊中插⼊恶意指令，覆盖原始Prompt⽬标。
- 越狱攻击：绕过模型安全限制⽣成违法/有害内容。
- 数据泄露攻击：诱导模型透露训练数据中的隐私信息。
- 模型欺骗：通过虚假前提误导模型输出错误答案。
- 拒绝服务攻击：提交超⻓/复杂Prompt消耗计算资源。
