### 发送短信验证码

- 在 Spring MVC / Spring Boot 的Controller 层 , 方法参数里写上 `HttpSession session`，调用方法时 Spring 会自动帮注入对应参数
- 参数本质上来自当前请求绑定的 `HttpServletRequest` , 在 Web 应用里 , 每个请求到来时Servlet 容器都会创建一个 `HttpServletRequest` 对象 , 该对象中有一个 `getSession()` 方法

**示例代码**
```java
@Override  
public Result sendCode(String phone, HttpSession session) {  
    // 1. 校验手机号码, 不符合返回错误信息  
    if(RegexUtils.isPhoneInvalid(phone)) {  
        return Result.fail("手机号格式错误");  
    }  
    // 2. 若符合, 生成验证码, 并将验证码保存到session  
    // 使用HuTool生成6位数字验证码  
    String code = RandomUtil.randomNumbers(6);  
    session.setAttribute("code", code);  
    // 3. 发送验证码给用户 (假设发了)  
    log.debug("发送短信验证码成功, code = " + code);  
    // 4. 返回ok  
    return Result.ok();  
}
```

### 使用短信验证码登录

- 使用 `ServiceImpl<UserMapper, User> implements IUserService` 后, 类内自带query方法, 可以用来查询; 类内自带save方法, 可以用来保存
- 用户名前缀可以设置常量专门存储, 方便解耦与管理
- Pojo中的User类可以事先绑定对应的表, 方便MP进行查询

**代码示例**
```java
private User createUserWithPhone(String phone) {  
    User user = new User();  
    user.setPhone(phone);  
    user.setCreateTime(LocalDateTime.now());  
    user.setNickName(
        SystemConstants.USER_NICK_NAME_PREFIX + 
        RandomUtil.randomString(10));  
    save(user);
    return user;
}
@Override  
public Result login(LoginFormDTO loginForm, HttpSession session) {  
    // 1. 校验手机号和验证码, 不一致则报错  
    String phone = loginForm.getPhone();  
  
    if(RegexUtils.isPhoneInvalid(phone)) {  
        return Result.fail("手机号格式错误");  
    }  
  
    Object cacheCode = session.getAttribute("code");  
    String code = loginForm.getCode();  
    if(cacheCode == null || cacheCode.toString().equals(code)) {  
        return Result.fail("请输入正确的验证码");  
    }  
    // 2. 一致, 则根据手机号查询用户  
    User user = query().eq("phone", phone).one();  
    // 3. 判断用户是否存在, 不存在则创建新用户  
    if(user == null) {  
        user = createUserWithPhone(phone);  
    }  
    // 4. 保存用户信息到session中  
    session.setAttribute("user", user);  
    return Result.ok();
}
```


### 验证登录

- 用户登录时, 要校验用户信息是否存在于session
- 由于很多功能都需要校验用户登录, 所以使用拦截器判断用户
- 拦截过程中要注意线程安全问题, 所以将需要返回的用户信息保存到ThreadLocal中
- ThreadLocal是静态的, 其相关信息保存在当前线程中

**配置拦截器**
```java
// 在进入方法之前进行处理  
@Override  
public boolean preHandle(HttpServletRequest request, 
                         HttpServletResponse response, 
                         Object handler) throws Exception {  
    // 1. 获取session以及其中的用户  
    HttpSession session = request.getSession();  
    Object user = session.getAttribute("user");  
    // 2. 判断用户是否存在, 不存在则拦截  
    if(user == null) {  
        // 返回 401(未授权) 状态码  
        response.setStatus(401);  
        return false;    }  
    // 3. 存在则将信息保存在ThreadLocal  
    UserHolder.saveUser( (UserDTO) user);  
    // 4. 放行  
    return true;  
}  

// 返回给用户之前, 销毁分配的对象  
@Override  
public void afterCompletion(HttpServletRequest request, 
                            HttpServletResponse response, 
                            Object handler, Exception ex) 
                            throws Exception {  
    // 移除用户 
    UserHolder.removeUser();  
}
```

**配置拦截路径**

**Controller返回**

**DTO优化**
- 由于直接返回User信息, 可能导致用户敏感信息泄露, 而且过多的信息量也会过多占用session空间, 即Tomcat内存空间, 所以可以使用UserDTO简化信息
- User类型到UserDTO类型, 可以使用HuTool中的工具
- `BeanUtil.copyProperties(user, UserDTO.class);`
```java
User user = query().eq("phone", phone).one();  
if(user == null) {  
    user = createUserWithPhone(phone);  
}  
session.setAttribute("user", 
    BeanUtil.copyProperties(user, UserDTO.class));  
```


# 集群Session

### 共享问题

- 多台Tomcat并不共享Session空间, 如果请求在不同的Tomcat服务器之间切换进行, 则会导致数据丢失的问题
- 若要解决多台服务器之间的session共享问题, 则该方案应该满足
	- 数据共享
	- 内存存储
	- 键值对结构

### Redis方案

- 临时信息保存时, 不应该被直接存储到session, 而是应该存储到Redis当中
- Redis中, key的设计要同时结合两个字段, 以同时标明用户信息和字段信息, 如 `phone:手机号`, `token:用户`
- Redis中的key最好设置一个有效期, 防止数据在内存中堆积
- 使用Token, tomcat不会将其自动返回到浏览器, 需要手动返回到客户端
- 当前端获取到token后, 每次请求都会在其请求头中加入, 通常使用拦截器的方法
	- `if(token) config.headers['authorization'] = token`
	- 并使用 `request.getHeader("authorization")` 获取token
- Redis中, 对普通数据使用String类型, 类对象数据使用Hash类型
	- String类型将对象以JSON字符串保存, 比较直观
	- Hash类型将对象中的每个字段独立存储, 可以针对单个字符做CRUD, 并且内存占用更少

##### 保存用户信息
- 使用HuTool工具中的UUID生成随机字符串, 参数true表示简单模式
- 使用HuTool工具中的beanToMap将对象转为Map, 方便使用putAll批量插入
- 使用putAll时, 无法指定记录的有效期, 所以要在插入后使用expire进行指定
```java
@Override  
public Result login(LoginFormDTO loginForm, HttpSession session) {  
    ...
    // 从redis中获取code  
    String cacheCode = template.opsForValue()
            .get(RedisConstants.LOGIN_CODE_KEY + phone);  
    ...
    // 4. 保存用户信息到redis中  
    // 4.1 随机生成token, 作为登录令牌  
    UUID token = UUID.randomUUID(true);  
    // 4.2 将User对象转为HashMap存储  
    UserDTO userDTO = BeanUtil.copyProperties(user, UserDTO.class);  
    Map<String, Object> userMap = BeanUtil.beanToMap(userDTO);  
    // 4.3 存储  
    template.opsForHash()
        .putAll(RedisConstants.LOGIN_USER_KEY + token, userMap);  
    template.expire(RedisConstants.LOGIN_USER_KEY + token, 
                    RedisConstants.LOGIN_USER_TTL, 
                    TimeUnit.MINUTES);  
    // 5. 返回token
    return Result.ok(token);  
}
```

##### 更新Redis有效期
- 只要用户不停访问Redis, 则记录有效期不断更新
- 在拦截器校验用户登录状态操作中更新有效期
- 由于拦截器不由Spring管理, 所以不能进行依赖注入, 需要自己手动管理其中的类
- 由于StringRedisTemplate只接受String类型, 所以必须使用一定手段将传入的Map中的各个字段都转为String类型
```java
@Override  
public boolean preHandle(HttpServletRequest request, 
                         HttpServletResponse response, 
                         Object handler) throws Exception {  
    // 1. 获取请求头中的token, 通过  
    String token = request.getHeader("authorization");  
    if(StrUtil.isBlank(token)) {  
        return false;    
    }  
    String tokenKey = RedisConstants.LOGIN_USER_KEY + token;  
    Map<Object, Object> userMap = 
        stringRedisTemplate.opsForHash().entries(tokenKey);  
    // 2. 判断用户是否存在, 不存在则拦截  
    if(userMap.isEmpty()) {  
        // 返回 401(未授权) 状态码  
        response.setStatus(401);  
        return false;    
    }  
    // 3. 存在则将信息保存在ThreadLocal
    UserDTO user = 
        BeanUtil.fillBeanWithMap(userMap, new UserDTO(), false);  
    UserHolder.saveUser(user);  
    // 4. 刷新token有效期  
    stringRedisTemplate.expire(tokenKey, 
        RedisConstants.LOGIN_USER_TTL, TimeUnit.MINUTES);  
    // 5. 放行  
    return true;  
}
```


##### 登录拦截器优化

- 对于原来的拦截器, 只会拦截那些需要登录的路径, 如果用户登录后一直在访问那些不需要拦截的路径, 此时即使用户一直在线, 也会因为没能刷新有效期而导致登录过期
- 针对此缺陷, 应当在原拦截器的基础上添加一层拦截器, 该拦截器拦截一切访问路径, 专门负责用户token的刷新, 不在乎token存在与否, 刷新完token(或者什么都不做)后直接放行

**配置拦截器**
- 通过控制拦截器的order, 可以确保拦截器的执行顺序
- 也可以不添加, 默认先添加的拦截器先执行
```java
@Override  
public void addInterceptors(InterceptorRegistry registry) {  
    registry.addInterceptor(new LoginInterceptor())  
            .excludePathPatterns(  
                    "/user/code",  
                    "/user/login",  
                    "/blog/hot",  
                    "/shop/**",  
                    "/shop-type/**",  
                    "/upload/**",  
                    "/voucher/**"  
            ).order(1);  
    registry.addInterceptor(new RefreshTokenInterceptor(stringRedisTemplate)).order(0);  
}
```

@Override  
public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {  
  
    String token = request.getHeader("authorization");  
    if(StrUtil.isBlank(token)) {  
        return true;

    String tokenKey = RedisConstants.LOGIN_USER_KEY + token;

    return true;}
