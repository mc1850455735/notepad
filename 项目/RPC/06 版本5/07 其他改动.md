
# Common部分
- `RpcResponse.fail` 中动态传入字符串作为错误信息, 非默认字符串
- `MyDecoder` 中, 对传入数据流的字节数进行检查
- 新增自定义异常 `SerializeException`, 区分序列化发出的异常信息
- `Serializer` 中使用 `Map` 存储序列化器, 保证每个序列化器只创建一次

# Client
- 将 `ServerCache` 缓存中的存储服务更为线程安全的 `ConcurrentHashMap`
- 在删除服务 `delete` 方法中, 对空地址列表逻辑进行了判断
- 在 `getServiceListFromCache` 获取服务地址方法中, 找不到对应服务返回空列表而不是 null, 避免调用时出现空指针异常
- 同理, `CircuitBreakerProvider` 中 `HashMap` 改为 `ConcurrentHashMap`, 避免了多线程访问时可能出现的同步问题. 避免了在 `getCircuitBreaker` 中显式使用 `synchronized` 关键字, 提高了方法性能
- 通过 `ConcurrentHashMap` 类的 `computeIfAbsent` 方法, 避免了手动同步逻辑, 该方法会在 `Map` 中查找指定的 key, 如果不存在, 则通过指定的函数来生成一个新的值, 插入到 Map 中并返回

# Server
- 在 NettyRpcServer 中加入判空逻辑, 当 request 为 null 时, 直接返回
- 限流器中, 将存储限流器的 Map 类型改为线程安全的 `ConcurrentHashMap` , 同时也使用 `computeIfAbsent` 简化代码, 插入默认值
- `TokenBucketRateLimitImpl` 令牌桶算法实现中, 将其中的 `RATE` 和 `CAPACITY` 由静态变量改为实例变量, 避免了全局变量的使用, 从而使每个实例都拥有独立的限流配置
- `getToken` 方法中, 只在桶容量更新的临界区才加锁, 降低了同步对性能的影响
