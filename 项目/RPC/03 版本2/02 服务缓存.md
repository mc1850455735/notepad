# 概述

**建立本地Cache**
- 在客户端创建本地缓存Cache

**更改ServiceDiscovery**
- 申请缓存时优先查找本地缓存提高速度

**执行流程**
- 监听机制的关键在于 watcher 的定义, 使用 `CuratorCache` 实现 `watcher`, 在 `CuratorCache` 中添加 listener, 并判断节点改变的类型属于何种, 使用 switch 分别处理各个不同的节点改变方式
- 如果 zookeeper 中节点创建, 检验合法性后, 直接将对应节点加入本地缓存; 若检测到节点修改, 则在本地缓存中将新值替代老值; 若节点删除, 则直接在本地缓存中移除相应地址值
- 本地缓存实际上就是一个 map 数据类型, 存储对应服务名下的多个服务实例地址, 使用 List 类型进行管理. 添加/修改/删除本地缓存的过程实际上就是操作 map 以及其中的 list
- 客户端寻找服务实例时, 先查找本地缓存, 如果本地缓存不存在, 则去 zookeeper 中寻找. 

# 动态缓存机制

**旁路缓存策略**
- cache aside, 即旁路缓存机制
- 首先到本地缓存中读取, 如果本地缓存中查找不到, 再去注册中心查找
- **存在的问题**: 如果注册中心中对于某个服务添加了一个新的地址, 但是由于客户端始终可以在本地缓存查找到该地址, 所以注册中心中新的地址不会被加入到客户端本地缓存, 从而无法被使用

**事件监听**
- 在 Zookeeper 中注册监听器 Watcher, 监听注册中心的变换, 变化时主动更新本地缓存, 实现本地缓存的动态更新

# 事件监听机制

### Watcher概念
- Zookeeper 提供了数据的 发布/订阅 功能, 多个订阅者可以同时监听某一特定主题对象, 当该主题对象自身状态发生变化时, 如节点自身内容变化或节点下的子节点列表变化, 会实时主动的通知所有订阅者
- zookeeper 采用了 watcher 机制实现数据的发布订阅功能. 该机制在被订阅对象发生变化时会异步通知客户端, 因此客户端不必在 watcher 注册后轮询阻塞, 从而减轻了客户端压力
- watcher 机制事件上与观察者模式类似, 可以看作是一种观察者模式在分布式场景下的实现方式

### Watcher架构
- watcher 机制的实现由三部分组成
	- `zookeeper` 客户端
	- `zookeeper` 服务端
	- `ZKWatchManager` 对象
- 客户端首先将 Watcher 注册到服务端, 同时将 Watcher 对象保存到客户端的 `watch` 管理器中. 当 `zookeeper` 服务端监听的数据状态发生变化时, `zookeeper` 服务端会主动通知客户端, 随后客户端 watch 管理器会触发相关的 watcher 回调处理相应逻辑, 完成发布订阅流程

# ServiceCache

**cache中Map作用**
- key 表示 服务名, serviceName
- value 表示 服务提供者列表, 为String类型的List
- 通过Map, 在本地保存每个服务对应的服务提供者地址列表
- ServiceCache 封装了一系列方法用于操作 map 缓存

# ZKServiceCenter

**cache缓存**
- 在服务管理中心中先加入cache缓存字段
- 进行服务发现时, 先寻找本地缓存, 本地缓存找不到后再查找 zookeeper

**zookeeper查询语句**
- 使用 zookeeper 客户端 api 获取指定路径下的所有节点, 存入 serviceList 中
- getChildren() 方法的作用是获取指定节点(路径)的所有子节点, 该方法返回一个 `GetChildrenBuilder` 对象, 允许通过其设置其他选项, 如是否需要递归等, 随后通过 `forPath()` 获取具体数据
- `forPath(String path)` 是 `GetChildrenBuilder` 接口的方法, 通过该方法在指定的命名空间中接收一个 `zookeeper` 路径作为参数, 表示对该路径进行操作
- 在该调用中, forPath方法会返回该路径下的所有子节点名称列表, 即该路径下所有注册的服务实例名称, 返回类型为 `List<String>`
```java
serviceList = client.getChildren().forPath("/" + serviceName);
```

# watchZK

**监听器添加**
- 该代码为 `curatorCache` 注册一个事件监听器, 当 zookeeper 中监视的节点发生变化时, 指定的事件处理逻辑就会被触发
- CuratorCache 是 Curator 提供的一个类, 用于监视 Zookeeper 中路径的变化.
- `listenable()` 方法会返回一个可以添加监听器的对象, 即 Listenable 接口, 该接口允许注册事件监听器
- `addListener` 是 `Listenable` 接口提供的方法, 用来为缓存添加监听器
- `CuratorCacheListener` 是 Curator 框架提供的一个接口, 定义了节点变化时的回调方法
```java
CuratorCache curatorCache = CuratorCache.build(client, "/");
curatorCache.listenable().addListener(new CuratorCacheListener());
```

**event函数参数**
- **Type** : 事件类型
- **ChildData childData** : 更新前节点状态和数据
- **ChildData childData1** : 更新后节点状态和数据
