# 概述

### Netty中的重要组件
- ChannelHandler 是对 Channel 中数据的处理器, 这些处理器可以是系统本身定义的编解码器等, 也可以是用户自定义的处理器
- 这些处理器会被统一加入到 ChannelPipeline 对象中, 并按照类别与添加的顺序对 Channel 中的数据依次进行处理

### 自定义编解码器优势
- 使用自定义编解码器, 将编码与解码的过程进行封装, 简化了代码的开发流程, 提高了代码的可阅读性
- 在内部实现对消息头的加工, 从而解决粘包问题
- 消息头中可以加入 `messageType` 消息类型, 对消息读取机制进一步的扩展

# Serializer

**概述**
- 序列化器接口, 提供将对象序列化为字节数组, 或者是将字节数组反序列化为对象的方法

**序列化的目的**
- 网络通信中, 数据只能以字节流的方式进行传输, 将对象序列化为字节数组后, 可以通过网络传输, 并在接收方反序列化为原始对象
- 字节数组是一种通用的数据表达形式, 不依赖于具体的语言实现

# ObjectSerializer

**序列化过程**
- 在 serialize 方法中, 使用 `ByteArrayOutputStream` 作为输出流, 其会在内存中创建一个动态缓冲区, 用于存储序列化后的字节数据
- 使用对象输出流, 即 `ObjectOutputStream` 对 bos 其进行包装, 将输出的对象字节流写入缓冲区, 实现使用 java.io 的对象序列化
- 调用 `writeObject` 方法, 触发对象的序列化, 将结果保存到 bos 中; 随后使用 bos 的 `toByteArray` 获取缓存区中转换后的字节数组, 并返回该字节数组

**反序列化过程**
- 在 `ObjectSerializer` 中, 不需要 `messageType` 的参与
- 在 `deserialize` 方法中, 使用 `ByteArrayInputStream` 作为输入流, 将传入的字节数组包装为字节输入流
- 使用 `ObjectInputStream` 对象输入流包装 bis, 以支持反序列化
- 调用 `readObject`, 将读取到的字节流反序列化为 Object 类型的对象
- 返回反序列化的 Object 对象

# JsonSerializer

**序列化**
- 序列化过程中, 使用 `fastjson` 自带的 `JSONObject.toJSONBytes` 方法, 将任意对象转换为 `JSON` 格式的字节数组
```java
byte[] bytes = JSONObject.toJSONBytes(obj);  
return bytes;
```

**反序列化**
- 反序列化过程中, 通过 fastjson 库中的 JSON.parseObject 方法, 传入字节数组和数据类型, 将传入的字节数组转为 request 对象
- 根据 messageType 决定转换对象的类型, messageType 为一个整数.
- 由于 Request 中存在参数列表和参数类型列表, 但是 fastjson 在转换过程中可能出现类型上的错误, 所以需要参考 paramsType 转换 params 中各个元素的类型; 如果类型一致, 则直接使用; 类型不一致, 则转换后再使用
- 同理, 对 Response 中使用 Object 保存的 data, 也需要进行类型的转换

**Request反序列化**
- `isAssignableFrom` : 用于判断反序列化后的参数类型是否与指定参数类型列表内的参数类型一致, 不一致则需要转换
- `JSONObject.toJavaObject` 用于将 `JSONObject` 类型的对象转为给定类型的对象, 给定的类型即为参数类型列表中的类型
- 之所以还需要对内部的 params 进行转换, 是因为 `parseObject` 方法只对对象的顶层进行转换, 如果对象中还存在嵌套的结构, 则嵌套结构内部的类型 (即 params 数组中的元素 ) 无法被转化, 依然为 JSONObject 格式, 需要重新使用 `JSONObject.toJavaObject` 进行递归转换
```java
RpcRequest request = JSON.parseObject(bytes, RpcRequest.class);
Object[] objects = new Object[request.getParams().length];
for (int i = 0; i < objects.length; i++) {
    Class<?> paramsType = request.getParamsType()[i];
    if (!paramsType.isAssignableFrom(request.getParams()[i].getClass())) {
        objects[i] = JSONObject.toJavaObject(
            (JSONObject) request.getParams()[i], 
            request.getParamsType()[i]
        );
    } else {
        objects[i] = request.getParams()[i];
    }
}
request.setParams(objects);
obj = request;
```

**Response反序列化**
- 直接使用 getDataType 和 setData, 将 data 转为正确的类型
```java
RpcResponse response = JSON.parseObject(bytes, RpcResponse.class);  
Class<?> dataType = response.getDataType();  
if (!dataType.isAssignableFrom(response.getData().getClass())) {  
    response.setData(JSONObject.toJavaObject((JSONObject) response.getData(), dataType));  
}  
obj = response;
```

# MessageType
- 枚举类型, 定义了消息的请求 Request 和 消息的响应 Response 两个枚举值

# MyEncoder

**继承MessageToByteEncoder**
- MessageToByteEncoder 是 netty 专门用来实现编码器的抽象类, 可以帮助开发者将 Java 对象编码成字节数组

**构造器参数**
- `ChannelHandlerContext` : Netty 提供的上下文信息, 代表 pipeline 管道的上下文, 包括 Channel 和处理器相关信息
- `Object msg` : 需要进行编码的消息对象
- `ByteBuf out` : Netty 提供的字节缓冲区, 将编码后的字节数组存入其中

**消息写入**
- 消息的传递通过传入构造函数的 buf 进行
- 通过 `writeShort()` 方法, 将对应的消息类型, 序列化方式等较短的标识符信息等写入 buf; 
- 通过 `writeInt()` 方法, 将消息总长度等信息写入 buf; 
- 通过 `writeBytes` 方法, 将对象序列化后的字节数组写入 buf

# MyDecoder

**构造器参数**
- `ChannelHandlerContext` : 作用同 `MyEncoder`
- `ByteBuf in` : 传入的 buf 信息, 包括消息类型, 序列化方式等, 详见上
- `List<Object> out` : 通过 buf 信息, 可能解析出一个或多个 `Object`, 将解析结果存入 out 中, 方便后续使用

**消息读取**
- 消息的传递通过传入构造函数的 in 进行
- 读取顺序和调用次数与 MyEncoder 中对应, MyEncoder 中写入几个参数, 用什么写入, 则在 MyDecoder 中就需要读出几个方式, 且读出方式需要一致
- 对于对象序列化后的字节数组, 还需要根据传入的参数额外指定需要的序列化/反序列化器
