
# 什么是RPC

- RPC全称 Remote Procedure Call, 远程过程调用.
- 通过RPC, 可以将复杂的远程通讯调用过程进行封装, 使在用户层可以像调用方法一样发起远程调用, 并为用户屏蔽通讯过程的复杂性
- RPC的实现是现代分布式和微服务系统的基础

# 协议

### 概述
- 协议即为数据通讯时, 用于理解双方信息传输方式的约定
- 设计协议时, 应当保证协议的可扩展性, 在协议头中应该留出足够的空间确保协议可以自由扩展, 做好扩展性是一个好协议设置的关键
- 通过保证协议的扩展, 可以实现协议的向下兼容, 确保使用旧协议的应用也可以读取传输过来的新协议内容

# 序列化
- 序列化就是将一个对象转换为可传输或者存储的格式, 通常用于数据持久化或者网络传输
- 数据序列化存在多种方式, 不管使用何种方式, 核心思想就是通过这种方式将对象的类型, 属性的类型和属性的值按照固定格式写入二进制字节流

### JDK原生
- 在Java中, 可以通过对象输出流, 将对象实现 Serializable 接口, 使其拥有被序列化为二进制流的能力, 并通过对象输出流进行输出

### JSON
- JSON是一种轻量级的, 基于文本的数据格式, 结构简单, 且具有良好的可读性
- 由于使用文本存储, 序列化的对象数据量应尽可能小, 否则传输过程会对性能产生较大的影响

### Hessian
- Hessian是一种高效二进制序列化协议, 适用于 Java 等语言的分布式系统通信, 尤其用于高性能 RPC 框架.
- Hessian 使用二进制算法进行序列化, 优点在于序列化后的数据量小, 传输速度快, 适合微服务之间的高效通信
- 然而, Hessian仍存在一些问题, 如不支持Java中的某些常见烈性, 比如 `LinkedHashMap` 等 Linked 系列集合. 且在反序列化Byte和Short时, 会将数据自动转换为Integer类型

**引入依赖**
```xml
<dependency>  
    <groupId>com.caucho</groupId>  
    <artifactId>hessian</artifactId>  
    <version>4.0.66</version>  
</dependency>
```
**序列化**
```java
Student stu = new Student("xiaoming", 25);  
ByteArrayOutputStream baos = new ByteArrayOutputStream();  
HessianOutput hessianOutput = new HessianOutput(baos);  
hessianOutput.writeObject(stu);  
byte[] bytes = baos.toByteArray();  
hessianOutput.close();  
baos.close();
```
**反序列化**
```java
ByteArrayInputStream bais = new ByteArrayInputStream(bytes);  
HessianInput hessianInput = new HessianInput(bais);  
Student result = (Student) hessianInput.readObject();  
System.out.println(result);  
hessianInput.close();  
bais.close();
```

### Protobuf
- Protocol Buffers 是一个由Google公司开发的高效, 语言中立, 平台仲里的序列化结构数据格式, 相比较JSON和XML更加高效, 数据量较大时可以显著减少传输和存储过程中的开销

**使用**
1. 安装
2. 定义 `.proto` 文件
```proto
syntax = "proto3";  
  
package top.majinliang;  
  
message Person {  
  string name = 1;  
  int32 age = 2;  
  string email = 3;  
}
```
3. 编译 `.proto` 文件为 Java 类
```shell
protoc --java_out=./ person.proto
```
4. 使用生成的类进行序列化和反序列化
```java
Person person = PersonOuterClass.Person.newBuilder()
    .setName("Alice")
    .setAge(25)
    .setEmail("1123123")
    .build();
```
- 序列化
```java
byte[] bytes = person.toByteArray();
System.out.println(Arrays.toString(bytes));
```
- 反序列化
```java
Person resultPerson = Person.parseFrom(bytes);  
System.out.println(resultPerson);
```

# 动态代理

**概念**
- 动态代理是面向对象编程中的一种设计模式, 它允许在运行过程中动态的创建代理类, 用来代替真实对象执行任务
- 代理类是一种概念, 存在动态代理与静态代理, 其作用是替代真实对象执行任务, 为已有的对象提供替代品.
- 静态代理在编码阶段就已经确定, 而动态代理是在运行阶段根据需求动态的生成代理类, 相比较静态代理类, 通常动态代理类更加灵活. 静态代理需要为每一个类都提供一个代理, 而动态代理只需要提供一个通用的代理类即可

**标准**
- 代理类的生成性能: 生成速度越快, 字节码越小越优
- 代理类的执行效率: 代理类的主要作用是对接口方法进行拦截, 每次调用接口方法时, 都会进行代理逻辑, 所以要求代理类执行效率足够高
- 框架易用性

### JDK动态代理

**实现**
- 通过 Java 自带的 java.lang.reflect.Proxy 和 InvocationHandler 接口生成代理对象, 要求被代理对象必须实现一个或者多个接口

**场景**
- 适用于接口驱动的RPC场景
- 被代理的服务接口明确且稳定, 且不需要代理具体的类

**优缺点**
- **优点**: JDK自带, 生成的代理类较轻量级, 效率较高
- **缺点**: 只能代理实现了接口的类, 无法代理普通类; 性能上不如 CGLIB

### CGLIB动态代理

**实现**
- 基于ASM库, 使用继承的方式实现代理, 通过生成目标类的子类, 能代理所有非final类的非final方法, 不需要接口支持

**场景**
- 适用于类驱动的RPC场景, 尤其是要代理没有接口的类时
- 被代理类不便或不能实现接口, 或者需要代理大量的类

**优缺点**
- **优点**: 可以代理没有接口的类, 性能优于JDK
- **缺点**: 使用字节码生成, 生成效率低; 需要额外库支持; 生成的代理类比JDK代理类较大

### Javasist动态代理

**实现**
- 基于字节码操作的代理结束, 通过修改字节码实现代理. javassist也可以直接生成类的字节码, 但是生成方式较灵活

**场景**
- 适用于需要更复杂字节码操作的RPC框架
- 需要在运行时修改类结构, 或者需要定制化生成的代理类

**优缺点**
- **优点**: 生成字节码速度较快, 且代码更易理解; 高并发下效率优于CGLIB
- **缺点**: 与JDK相比更复杂; 生成的字节码代理类较大
