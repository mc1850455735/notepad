# Controller

```java
@PostMapping(value = "/api/resumes/upload", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
@RateLimit(dimensions = {RateLimit.Dimension.GLOBAL, RateLimit.Dimension.IP}, count = 5)
public Result<Map<String, Object>> uploadAndAnalyze(@RequestParam("file") MultipartFile file) {
    Map<String, Object> result = uploadService.uploadAndAnalyze(file);
    boolean isDuplicate = (Boolean) result.get("duplicate");
    if (isDuplicate) {
        return Result.success("检测到相同简历，已返回历史分析结果", result);
    }
    return Result.success(result);
}
```

对于注解 `@PostMapping(value = "/api/resumes/upload", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)`，其中 `consumes = MediaType.MULTIPART_FORM_DATA_VALUE)`  表示该接口接收的是表单文件上传请求, 也就是 `multipart/form-data` 格式。

对于注解 `@RateLimit(dimensions = {RateLimit.Dimension.GLOBAL, RateLimit.Dimension.IP}, count = 5)`，这是一个限流注解, 表示该接口将从全局和IP的维度进行访问限制, 避免对文件上传的恶意攻击。

`MultipartFile` 类型是 `SpringBoot` 中用于接收上传文件的对象，可以获取文件的各类信息；随后通过 `uploadService.uploadAndAnalyze` 进行简历加载和分析。

```java
@GetMapping("/api/resumes/{id}/export")
public ResponseEntity<byte[]> exportAnalysisPdf(@PathVariable Long id) {
    try {
        var result = historyService.exportAnalysisPdf(id);
        String filename = URLEncoder.encode(result.filename(), StandardCharsets.UTF_8);

        return ResponseEntity.ok()
            .header(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename*=UTF-8''" + filename)
            .contentType(MediaType.APPLICATION_PDF)
            .body(result.pdfBytes());
    } catch (Exception e) {
        log.error("导出PDF失败: resumeId={}", id, e);
        return ResponseEntity.internalServerError().build();
    }
}
```

这个方法中通过 `historyService.exportAnalysisPdf` 获取简历分析报告，并将文件名编码为 UTF-8，经过编码后，可以更安全地放入 HTTP 响应头中，让浏览器正确识别下载文件名。

`header(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename*=UTF-8''" + filename)` 部分用于告诉浏览器，该返回内容是一个文件类型的附件，文件名为xxx。这一部分主要用于给浏览器声明处理该响应的方式为附件以及声明文件名。

同时，通过 `contentType` 设置相应内容类型为 PDF 文件，确保浏览器将该二进制流以 pdf 格式进行处理；最后，通过 body 将 PDF 的二进制内容写入响应体中。文件本质上是二进制流， 所以返回类型为 `ResponseEntity<byte[]>`。

如果失败，则记录日志并返回错误码。

# Service

## UploadService

`uploadAndAnalyze` 方法，是一个异步处理简历分析任务的方法，其作用是校验解析文件后将简历解析任务加入到异步队列中，具体流程如下：

```
文件校验
  ↓
文件类型识别
  ↓
简历去重
  ↓
简历文本解析
  ↓
文件上传到 RustFS
  ↓
简历信息保存到数据库
  ↓
发送分析任务到 Redis Stream
  ↓
返回上传结果
```

最终返回的是一个 `Map<String, Object>`，其中包含简历 ID、文件名、分析状态、存储地址以及是否重复等信息。

当用户传入的简历重复时，调用 `handleDuplicateResume` 方法进行重复处理。当该简历已有分析结果时，直接返回分析结果；否则返回简历的相关信息，并返回当前简历的分析状态。

当用户请求重新分析简历时，应作出如下处理：

首先，从数据库中通过简历 id 获取其简历，随后获取解析后的简历内容，如果不存在已缓存的简历内容，那么就重新进行一次解析并缓存；随后将简历状态改为 PENDING 后保存到数据库，并将处理该简历的任务加入队列。
